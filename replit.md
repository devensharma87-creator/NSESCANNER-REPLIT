# Workspace

## Overview

pnpm workspace monorepo using TypeScript. Each package manages its own dependencies.

## Stack

- **Monorepo tool**: pnpm workspaces
- **Node.js version**: 24
- **Package manager**: pnpm
- **TypeScript version**: 5.9
- **API framework**: Express 5
- **Database**: PostgreSQL + Drizzle ORM
- **Validation**: Zod (`zod/v4`), `drizzle-zod`
- **API codegen**: Orval (from OpenAPI spec)
- **Build**: esbuild (CJS bundle)

## Key Commands

- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- `pnpm --filter @workspace/api-server run dev` — run API server locally

See the `pnpm-workspace` skill for workspace structure, TypeScript setup, and package details.

## Artifacts

- **api-server** (`artifacts/api-server`) — Express API. Routes under `/api/*` (scanner, market summary, index detail, stock detail, options, news, provider status). Yahoo is the live data source; `lib/dataProvider.ts` is a scaffold for switching to Zerodha Kite when KITE_API_KEY/SECRET/ACCESS_TOKEN are set.
- **scanner** (`artifacts/scanner`) — React + Vite NSE/BSE tracker. Pages: `/` dashboard (MMI gauge, clickable index cards w/ breadth), `/scanner` full table, `/index/:slug` index detail, `/stock/:symbol` enriched stock page (KeyStats + Sector Peers via Yahoo quoteSummary), `/sectors`, `/options`, `/news`.
- **mockup-sandbox** (`artifacts/mockup-sandbox`) — component preview server.

## NSE Scanner notes

- Stock universe defined in `artifacts/api-server/src/lib/universe.ts` (~280 NSE F&O / index constituents). `INDEX_CONSTITUENTS` maps each index slug → ticker list (NIFTY50, BANKNIFTY, FINNIFTY, IT, AUTO, PHARMA, FMCG, METAL, REALTY, ENERGY).
- `breadth.adRatio` is `null` when decliners=0 and advancers>0 (UI renders "∞").
- Fundamentals fetched lazily via `fetchFundamentals()` (Yahoo quoteSummary, 1h cache).
- **Option Chain (T002)**: `lib/optionChain.ts` orchestrates two sources for `/api/options/chain/:underlying` — (1) Kite Connect (`lib/kiteOptionChain.ts`, primary, works from any IP when user has authenticated daily) using NFO instrument dump + batched `getQuote`; (2) NSE direct (fallback, only works from Indian IPs). 15s response cache. F&O universe of 199 entries (5 indices + 194 equities, sector-grouped) lives in `artifacts/scanner/src/data/fnoUniverse.ts`. Chain page (`pages/option-chain.tsx`) has searchable picker, ATM-centered ±25-strike grid with OI/ΔOI heatmap, and informative error UI that shows live Kite-session state.
- **Deep Scan**: `lib/deepscan.ts` + `routes/deepscan.ts` expose `/api/deepscan/lookup?q=` (universe + 22 vetted Indian indices) and `/api/deepscan/snapshot/:symbol?range=&kind=` (5y Yahoo history → trimmed candles + EMA20/50/100/200 + rolling VWAP20 + 1M/3M/6M/1Y/3Y/5Y returns + fundamentals on stocks). Stock chart ticker uses `yahooTickerFor()` so renamed NSE symbols (ZOMATO→ETERNAL etc.) work. VWAP suppressed for indices (zero volume). `pages/deep-scan.tsx` is the search-driven detail page with composed price/EMA/VWAP chart, volume bars, returns grid, and key statistics.
- **Option Strategies (T003)**: `lib/blackScholes.ts` (BS price + Δ/Γ/Vega/Θ/Rho with Newton-Raphson IV solver and bisection fallback; `yearsToExpiry()` enforces 15:30 IST settlement for both DD-MMM-YYYY and ISO YYYY-MM-DD inputs) + `lib/optionStrategies.ts` (13 templates: Long/Short Call/Put, Long/Short Straddle, Long/Short Strangle, Bull Call/Bear Put/Bull Put/Bear Call Spread, Iron Condor, Iron Butterfly, Covered Call). Payoff math is **analytical, not just sampled**: max P/L computed at every kink (S=0, each strike, far tail) with unbounded direction inferred from sum-of-CE-slopes — so e.g. Long Put correctly shows max profit at S=0 and Covered Call correctly shows bounded max loss at S=0. Premiums prefer bid/ask mid over LTP; missing IV is recovered via the BS solver. Endpoint `GET /api/options/strategies/:underlying` returns all 13 with legs, net debit/credit, breakevens, payoff series (161 points ±35% spot for visualization), net Greeks, lognormal POP, R:R, and per-lot ₹ figures. Returns 503 with `kiteAuthenticated` flag when chain is unavailable. `pages/strategies.tsx` renders each as a card with Recharts payoff diagram (Area+Line + breakeven reference lines + you-are-here dot at live spot), legs table, and a "Recommended" filter that flags strategies matching current bias (BULLISH/BEARISH/NEUTRAL) + IV regime (LOW≤30 pct / HIGH≥70 pct).
- **F&O Intraday Signals (T004)**: `lib/optionSignals.ts` runs 4 detectors (Trend Continuation, VWAP Reclaim, Volume Breakout, EMA Pullback) + a Baseline Outlook fallback for every index in `OPTION_INDICES` (NIFTY/BANKNIFTY/FINNIFTY/MIDCPNIFTY/SENSEX/BANKEX). Confidence floor is 50 (down from 65 — 65 produced empty pages on choppy days). HTF (daily EMA50) bias is a **soft penalty** (`-12` confidence + `HTF_CONFLICT` tag), not a hard drop. RR < 1.5 is also advisory (tag `RR_LOW`), not a drop. Baseline always emits per index (tier `BASELINE`, setupKey `BASELINE` so it doesn't collide with high-conviction `TREND_CONTINUATION` in the session-level entry/SL/T1/T2 lock store) — bias resolves to `sessionChangePct` sign in tied/zero-vote case so e.g. NIFTY -1.3% reliably yields a SHORT bias card. `getOptionSignals()` returns `{signals, diagnostics{indicesConfigured,indicesWithBars,highConvictionCount,baselineCount,suppressed[]}}`; `/api/options/signals` adds `lastUpdated` + `marketState` (open/closed/pre_open via `lib/marketEvents.ts`). Each signal carries `tier` (`HIGH_CONVICTION`|`BASELINE`), `htfBias`, `htfConflict`, `dailyEma50`, and `tags[]` (`BASELINE`/`HTF_CONFLICT`/`RR_LOW`/`COUNTER_TREND`). 30s response cache.
- **TradingView Alerts (T005)**: `lib/tradingViewAlerts.ts` accepts rich webhook payloads — beyond the narrow `tv_alerts` DB columns it parses `stopLoss`, `target1`, `target2`, `riskRewardRatio` (auto-derived from SL/entry/T1 if not provided), `urgency`, `rationale`, `tags[]`, `setupKey`, `timeframe`, `note` from the request body and stores them inside the existing `raw` JSONB column (no schema migration). `pickFromRaw()` rehydrates them on read so the in-memory buffer and DB-backfilled alerts both surface the same shape. Frontend `components/tradingview-alerts.tsx` displays SL/T1/T2/RR with color thresholds (≥1.5 emerald, ≥1 yellow, <1 red), urgency-toned chips, tag chips, setupKey badge, and side/strategy/symbol filters. Includes 3 ready-to-paste Pine Script templates (EMA 9/21 cross, RSI divergence, Opening Range Breakout) accessible from a dropdown selector in the "How to connect" panel. Only the `POST /api/webhooks/tradingview` endpoint is publicly reachable (TradingView is server-to-server and authenticates via `TRADINGVIEW_WEBHOOK_SECRET`); GET/DELETE on the same path require the session cookie.
- **Auth gate (T006)**: `lib/auth.ts` enforces a signed HttpOnly session cookie (`scanner_session`, HMAC-SHA256 with `SESSION_SECRET`, SameSite=Lax, Secure in prod, 30-day rolling). `requireAuth` middleware exempts `/api/healthz`, `/api/auth/*`, `/api/kite/callback`, and **POST-only** `/api/webhooks/tradingview`. Frontend wraps the app in `LoginGate` which polls `/api/auth/status`. Rate limits: login 5/15-min/IP, webhooks 60/min/IP, general API 300/min/IP — `trust proxy` is enabled so Replit's CDN client IPs are honored.
- **Security Audit + System Status (T007)**: `lib/securityAudit.ts` runs 18 checks (config + 4 live loopback probes against the running server) covering auth, secrets, transport/cookies, headers, data handling, rate limiting, and dependencies — returns a 0–100 score. `lib/systemStatus.ts` collects a snapshot of every subsystem (API uptime, DB connectivity, Kite credentials/session/WebSocket, TradingView webhook auth + recent alerts, market state) plus singleflight-cached probes (60s TTL) of Yahoo, NSE, Moneycontrol, and Business Standard RSS. Endpoints `/api/security/audit` and `/api/system/status` (both auth-gated). Frontend pages `/audit` and `/status` poll every 60 s / 30 s respectively with auto-refresh toggles, grouped cards, severity badges, and remediation hints.
- **OI Insights (T009)**: 4th tab on `/oi-lab`, default landing tab. New endpoint `GET /api/options/oi-lab/insights/:underlying?expiry=&strikes=` (handler in `routes/oiLab.ts`) returns one rich payload computed by `computeOiInsights()` in `lib/oiLab.ts`: per-strike OI distribution (CE/PE OI + Δ OI + IV + buildup + per-strike PCR + per-strike pain payout), 4 aggregates (PCR(OI), Δ PCR, PCR(volume), max-pain + deviation% from spot), top-5 resistance/support clusters by OI, and a 5-band sentiment (`STRONGLY_BEARISH`..`STRONGLY_BULLISH`) scored on -100..+100 from four signals (PCR, Δ PCR, spot-vs-max-pain deviation, intraday OI flow asymmetry) plus a plain-English `marketInsight` line + `analysis` paragraph. Universe endpoint now uses `getDynamicFnoUniverse()` which pulls live F&O equity list from Kite NFO instruments dump (every name with a non-expired FUT contract) — 6 h cache; falls back to a static 40-name list when Kite isn't connected (was the cause of the "199 stocks" complaint — list is now ~210+ live, refreshed when NSE adds/removes F&O names). Frontend `InsightsTab` in `pages/oi-lab.tsx` (new `SentimentGauge` SVG half-donut) lays out: top bar with searchable underlying picker + spot/Δ + expiry chips + strikes-around chips (ATM/5/10/20/All); LEFT column with sentiment gauge card + market-insight card (toned to band) + analysis card; RIGHT column with main bar chart (4 views: OI Total / OI Change / per-strike PCR / Max Pain payout) showing Spot + Max-Pain reference lines, 3 small cards (OI Change, Total OI, PCR donut), and top R/S strike chips. 30 s auto-refresh.
- **Full NSE Coverage (T010)**: `lib/nseBhavcopy.ts` exposes `getAllSymbols()` returning the ~2486-symbol active NSE EQ list straight from the daily bhavcopy (already loaded for delivery%). New `lib/fullNseScanner.ts` is a lightweight per-symbol Yahoo intraday scanner (15m bars, 1d range, concurrency 8, 5-min refresh, dedup via `scanInFlight`) that emits the same `StockRow` shape as the curated 280-name scanner — RSI/EMA20/EMA50/ATR/VWAP/volume ratio + delivery% + a 5-band recommendation (`STRONG_BUY..STRONG_SELL`). Symbols failing 3 consecutive scans are rested 1h. Bhavcopy fallback: if NSE bhavcopy is unreachable, falls back to the curated `UNIVERSE` and tags `sourceDate: "degraded:curated-universe"` so cold-start outages still serve coverage. Per-row sanity guard drops anything with `|changePct| > 35%` (catches Yahoo's malformed `chartPreviousClose` for illiquid ETFs that otherwise produced 80,000% nonsense gainers like NV20). Routes `GET /api/scan/full-nse` (sortBy/order/signal/search/limit/offset; signal enum aligned to `STRONG_BUY|BUY|NEUTRAL|SELL|STRONG_SELL`) and `GET /api/scan/full-nse/status` (cache + last-scan stats). Scanner.ts also fixed to call `yahooTickerFor()` so renamed NSE symbols (ZOMATO→ETERNAL, MCDOWELL-N→UNITDSPR, NIPPONLIFE→NAM-INDIA, GMRINFRA→GMRAIRPORT) stop logging "delisted" warnings. **UI is merged into the Scanner page** (no separate `/full-nse` route or nav link) via a "F&O CURATED (~280) / FULL NSE EQ (~2486)" toggle in the Scanner header — selection persists in `localStorage`. When set to "Full NSE EQ" the page swaps to a `useFullNseStocks()` hook that fetches `/api/scan/full-nse` (250ms-debounced search), keeps all existing Scanner features intact (sector filter, signal filter, screen presets, 19-column sortable table, hover reasons), and shows a meta strip with last-scan latency / no-feed count / rested count / source date. Live numbers: ~2141 valid rows / 2486 universe / ~33 s scan / ~345 illiquid microcap failures (auto-rested).
- **Stocks To Watch (T011)**: New `/stocks-to-watch` page (nav: "To Watch") shows a daily two-column catalyst deck — GREEN "Stocks to Watch" (positive catalysts: order wins, new projects, results beats, approvals, acquisitions, upgrades, partnerships, guidance raises) and RED "Stocks to Avoid" (regulator probes / SEBI / fraud, penalties, downgrades, results misses, recalls, management exits, defaults, governance flags, contract losses). Pipeline (`lib/stocksToWatch.ts`, deterministic — no LLM): pull cached news from `getAllMarketNewsLive()` over the configurable lookback (default 24h), score each headline against 16 catalyst phrase rules with side+weight, resolve mentioned NSE symbols via `lib/symbolAlias.ts`, group by symbol, side wins by aggregate confidence, dominant headline becomes display + up to 3 supporting headlines kept as evidence (expandable). 30-min cache, background refresh. **Symbol resolver**: phrase matches against the curated `UNIVERSE` (~280 names) + a hand-curated alias dict (~150 short-forms like "ONGC/OIL"→ONGC, "AB REALTY"→ABREL, "L&T FINANCE"→LTF) — token-only matches are restricted to the curated UNIVERSE because raw bhavcopy includes English-word collisions (SUPREME, HEALTHY, IT, DIVIDEND, TECH, CONSUMER) that produced false positives. Sources extended in `lib/newsRss.ts` to 21 feeds: Moneycontrol (5), Mint (3), ET (5 incl. Earnings/Policy), CNBC TV18 (2), Business Standard (2), Investing.com (2), Yahoo Finance (1). Endpoint `GET /api/stocks-to-watch?lookback=24` returns `{asOf, lookbackHours, watch[], avoid[], scanned, matched, sources[]}`. Bloomberg and Google Finance don't expose free RSS for IN markets — omitted by design rather than mocked. Frontend page polls every 5 min, each card is clickable to `/stock/:symbol`, shows confidence as 1-3 dots, source pill, "X min ago" timestamp, expandable "+N more headlines" evidence.
- **OI Lab (T008)**: `lib/oiLab.ts` + `routes/oiLab.ts` — three intraday OI surfaces on a single `/oi-lab` page. (1) **Bulk Snapshot** — `POST /api/options/oi-lab/snapshot` fans out a Kite-only chain fetch (`fetchKiteOnlyChain` wraps `fetchKiteOptionChain` directly, bypassing NSE fallback so OI Lab is broker-data-only by design) across up to 50 underlyings (concurrency 6) and returns JSON or CSV (Content-Disposition attachment). (2) **OI Heatmap** — `GET /api/options/oi-lab/heatmap` loads NFO instruments, picks front-month FUT per F&O name, batches `getQuote` (400/call), classifies each into LONG_BUILDUP/SHORT_BUILDUP/SHORT_COVERING/LONG_UNWINDING/NEUTRAL by comparing today's price change vs OI change vs a per-session baseline (first quote of the day, in-memory). Classifier returns NEUTRAL whenever |oiChgPct|<0.5 (no fresh positions = no buildup, regardless of price drift). 30s response cache + in-flight Promise dedupe so concurrent callers share one Kite fetch (protects 1 req/sec quote quota). (3) **Intraday Tracker** — `start/stop/status/series` endpoints; in-memory ring buffer (max 600 snapshots) of option-chain analytics for up to 20 underlyings, sampled every N min via `setInterval`. Race-safe: `runToken` bumped on every start/stop invalidates stale tick writes; `tickInFlight` mutex skips overlapping ticks; per-symbol `getActiveSession()` check aborts mid-tick if Kite expires. All snapshots cleared on session loss. Frontend `pages/oi-lab.tsx` is one page with 3 tabs — Snapshot (chip-pickers + table + CSV/JSON download), Heatmap (5 bucket cards as filter chips + sortable table), Tracker (start/stop/interval controls + Recharts time-series for Spot vs MaxPain, PCR(OI), Call vs Put OI per selected underlying).
