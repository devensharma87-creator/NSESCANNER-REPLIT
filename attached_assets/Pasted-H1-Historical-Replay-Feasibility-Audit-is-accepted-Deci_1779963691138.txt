## Replay rules

For each reconstructable F&O paper trade:

1. Match by:

   * index,
   * strike,
   * option type mapping:

     * `CALL → CE`
     * `PUT → PE`
   * snapshot timestamp between `opened_at` and `exited_at`.

2. Expiry handling:

   Since `paper_trade_fo` does not store expiry, use one of these approaches:

   * If expiry can be inferred safely from available reasoning/snapshot context, use it and mark method as `inferred`.
   * If not, compute separate replay per candidate expiry and choose the most plausible path, but mark data quality as `approximate_expiry_ambiguous`.
   * If expiry ambiguity makes the result unreliable, mark trade as `insufficient`.

3. For each trade, compute:

   * min observed LTP,
   * max observed LTP,
   * approximate MFE amount,
   * approximate MAE amount,
   * approximate MFE%,
   * approximate MAE%,
   * first observed time reaching +30%,
   * first observed time reaching +50%,
   * first observed time reaching +60%,
   * whether +30 / +50 / +60 was reached,
   * snapshot count,
   * first snapshot time,
   * last snapshot time,
   * data-quality grade.

4. Shadow rules:

   Calculate approximate results for:

   * R1: full exit at +30%
   * R2: full exit at +60%
   * R3: 50% book at +30% + BE trail
   * R4: 50% book at +50% + BE trail
   * R5: full BE after +50% MFE

5. BE-trail caveat:

   Every BE-trail result must include the note:

```text
BE-trail result is approximate / upper-bound because snapshot cadence is ~5 minutes and intra-window tick ordering is unknown.
```

6. Data-quality grades:

Use:

```text
good_5min
approximate_expiry_ambiguous
insufficient_no_snapshots
insufficient_no_expiry_match
insufficient_midcpnifty_not_snapshotted
```
