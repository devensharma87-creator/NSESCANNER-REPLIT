PART B — DB POOL ZOMBIE CONNECTION HARDENING
============================================

Investigate and harden production DB pool behaviour.

Known issue:

* Direct fresh DB query works.
* App-side pooled Drizzle/pg query sometimes fails.
* Error pattern suggests stale/zombie TCP connections.

Audit:

1. DB pool creation/config.
2. idle timeout.
3. connection timeout.
4. max lifetime if supported.
5. keepalive settings.
6. retry behaviour on connection termination.
7. whether failed connection is evicted.
8. whether startup burst causes pool instability.
9. whether serverless/prod environment kills idle TCP sockets.

Implement safe hardening only if needed:

* TCP keepalive if supported.
* shorter idle timeout than platform/network idle kill.
* connection timeout classification.
* one safe retry on connection-terminated/session-read query only.
* evict bad connection.
* no infinite retry.
* no retry storm.
* no masking of real schema errors.

For Kite session read specifically:

* if DB query fails due to connection termination, retry once with fresh connection/pool-safe path.
* if session truly missing/expired, report honestly.
* never treat DB read failure as logged-in.
* never log access tokens.
