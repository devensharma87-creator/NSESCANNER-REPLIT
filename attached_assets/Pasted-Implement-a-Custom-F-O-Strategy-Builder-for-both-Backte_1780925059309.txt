Acceptance criteria:

User can create a custom strategy from UI.
User can select EMA, VWAP, Volume Profile, FVG/SMC, Fibonacci conditions.
User can combine rules using AND / OR groups.
User can define entry, stop-loss, target, trailing stop, max trades per day, session window.
Strategy can be backtested independently.
Strategy can be enabled/disabled for official signal generation.
Every signal must show reason:
Which rules passed
Which rules failed
Entry reason
Stop reason
Target reason
Rejection reason
No signal should fire unless entry is forward-reachable.
No stale trigger entries.
No trades outside 09:15–15:30 IST.
No synthetic fake result.
No future-looking bias.
No repainting.
Research/proxy results must stay labeled as proxy, not tradeable P&L.
Real Replay must still depend on captured option premiums.

Important warning:

Do not implement this as “select 5 indicators and generate trades.” That will produce garbage signals.

The builder needs three layers:

1. Market condition layer

Example: trend, range, volatility, VWAP position, EMA stack, VIX regime.

2. Setup layer

Example: VWAP reclaim, EMA retest, FVG retest, liquidity sweep, Fibonacci pullback.

3. Execution/risk layer

Example: entry trigger, stop, target, R:R, max distance from entry, time-left filter, daily trade cap.

Only when all three layers align should the engine generate a trade.

My blunt recommendation: start with EMA + VWAP + Fibonacci first.
Then add FVG/SMC.
Then add Fixed Volume Profile/TPO proxy last.

Why? Because Fixed Volume Profile is dangerous in your current setup because index volume is missing/zero. If the agent builds it blindly, it will either not fire or will create fake confidence.

The best first custom strategies to implement are:

EMA + VWAP Trend Pullback
VWAP Reclaim + EMA Trend Confirmation
Fibonacci Pullback in EMA Trend
Liquidity Sweep + VWAP Reclaim
FVG Retest + EMA/VWAP Confluence

Tell the agent clearly: performance first, signal count second. No random trades just to make the screen look active.
