# Gate 5 — Make persistence failure impossible to hide

Awaiting `_saveSnapshotToDb()` is insufficient if the function catches and suppresses failure.

Required contract:

```ts
type SnapshotPersistenceResult =
  | {
      ok: true;
      snapshotId: string;
      committedAt: string;
      sha256: string;
      durableStore: "POSTGRESQL";
    }
  | {
      ok: false;
      reasonCode: string;
      errorClass: string;
      durableStore: "POSTGRESQL";
    };
```

Required behaviour:

1. PostgreSQL is the authoritative durable store.
2. Local disk is non-authoritative cache only.
3. A snapshot is not reported as durable before transaction commit.
4. A failed PostgreSQL write must:

   * Return or throw an explicit failure
   * Preserve the previous durable snapshot
   * Increment a persistence-failure metric
   * Emit a structured diagnostic event
   * Keep `canAuthorizeUniverse=false` for the uncommitted snapshot
5. No caller may ignore `ok:false`.
6. No in-memory or disk snapshot created before failed persistence may become authoritative.
7. Database schema creation/migration remains additive and idempotent.
8. Normalized records, source metadata, effective date, retrieval time, validation result, row count, rejected count, schema version and SHA-256 must be persisted.

Inventory every caller of `_saveSnapshotToDb()` and prove it handles both result branches.
