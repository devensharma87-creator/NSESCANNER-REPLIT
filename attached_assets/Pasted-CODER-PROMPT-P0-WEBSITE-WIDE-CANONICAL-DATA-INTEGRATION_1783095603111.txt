CODER PROMPT — P0 WEBSITE-WIDE CANONICAL DATA INTEGRATION AUDIT + SINGLE SOURCE OF TRUTH FIX

Current owner concern:

The website still behaves like separate tabs are pulling and calculating their own data paths.

This is unacceptable for a professional market/trading platform.

A stock/index must have one canonical identity and one canonical OHLC/quote source per timeframe. The same data point must appear consistently across:

- Home
- Scanner
- Deep Scan
- Stock Intelligence
- Watchlist
- Charting
- Swing Cash Queue
- Paper Trading
- F&O / Options
- Option Chain
- Pre-market report
- Post-market report
- Infra Health
- Telegram alerts
- Reports
- Backtests

The infrastructure is mostly ready, but the app is not yet fully plugged into one truth layer.

This is now a P0 data-integration and data-accuracy task.

====================================================
CURRENT OBSERVED PROBLEMS
====================================================

1. Telegram F&O warmup alert still says:

F&O DATA WARMUP FAILED
NIFTY / BANKNIFTY / SENSEX
Reason: UNKNOWN
Detail: Live intraday bars missing despite active Kite session.

This is not professional. If the detail is known, the reason must not be UNKNOWN.

But we already have F&O diagnostics, global data-health, option-chain readiness, daily bars status, signal cycle status, and warmup alerts.

This means the pre-market Telegram report is not connected to the canonical F&O readiness source.

3. Swing Cash Queue and Paper Trading are not aligned.

Screenshot evidence:

- Swing Cash Queue shows RELIANCE as EXPIRED, broker disabled, approval does not place real order.
- Paper Trading shows INDUSINDBK opened as an auto paper trade from swing-style rules.
- Paper Trading has an Equity decision audit showing INDUSINDBK OPENED.
- Swing Cash Queue does not clearly show the corresponding lifecycle linkage / source / paper-trade connection.

Expected:

If a Swing auto decision opens a paper trade, the source decision, staged order, paper trade row, audit row, Telegram status, and report row must all be linked or clearly separated by design.

4. Pre/post-market Telegram still uses placeholder template sections.

Post-market says many things like:

- Market breadth unavailable
- Participant OI unavailable
- Level validation unavailable
- News unavailable
- Global status info-only
- See /page

This is not a professional report.

If data is not integrated, it should be collapsed into a footer. If data is available, actual values must be shown directly.

5. The app still has multiple local truth paths.

That must stop.

There must be canonical data contracts and every tab must either consume them or clearly document why not.
