The decision you have to make — and it's a correctness one, not convenience
This is the important part, and I put it in the file's footer because it changes whether your backtest is valid:
Index spot candles from Kite often return volume = 0 — indices aren't directly traded, so there's no volume. But your strategy uses VWAP (volume-weighted) and Volume Breakout, both of which need real volume. If you backtest on zero-volume spot data, those two pillars of your confluence gate are computed on garbage, and the verdict is meaningless.
Two honest paths:
Path A — backtest on index futures (near-month, rolled across expiries). Futures have real volume and track the index tightly. This is the correct choice for a volume-aware strategy. The cost is your developer has to resolve the near-month future token and roll it at each expiry — a bit more work.
Path B — keep spot, make VWAP volume-agnostic. Simpler, but then it's not a true VWAP, and it won't match what your live system does if live VWAP uses a real volume feed.
The rule that decides it: the backtest must use the same volume basis as the live system, or the comparison is invalid. So the real question is — what does your live VWAP compute from right now? If your live system derives index VWAP from a volume feed (likely the futures or a synthetic), the backtest must use that same basis.
This is exactly the kind of question your developer can answer in five minutes by checking the live VWAP source, and it's worth answering before you run the fetch — because it determines whether you fetch spot or futures.
