# Pro Market Analyzer — F&O Trading Command Center
**v1.3** · Single-pane live market dashboard for Indian F&O traders.

A professional-grade trading tool that fuses Kite broker data, NSE option chain, yfinance, and a Black-Scholes pricing engine into one Streamlit application with 9 tabs.

## What's new in v1.3

- **🔴 Live mode** in Strategy Builder — Greeks and payoff auto-refresh from WebSocket or chain as the market moves
- **📈 Trade Simulator** — save strategies as virtual positions, mark to market in real time, track per-leg P&L, close/realize positions, see win-rate stats
- **📊 IV Rank & Percentile** — SQLite-backed historical IV tracking. Tells you if today's IV is statistically cheap or expensive based on the last 365 days. Auto-captures daily ATM IV per symbol.
- **Finer-grained auto-refresh** — 5s/15s/30s/60s options in sidebar
- **Bug fixes & polish** — cleaner error handling, unified data flow, removed dead imports

## How each new v1.3 feature works

### Live mode in Strategy Builder

Toggle the `🔴 Live` switch above the leg editor. When ON:
- Leg premiums refresh from WebSocket (if connected) or NSE chain
- Greeks recalculate against current premiums and IVs
- Payoff T+0 curve updates with each refresh
- Your entered IVs are preserved (live mode is a display overlay, not a destructive update)

Combine with the sidebar auto-refresh dropdown (5s/15s/30s/60s) for true continuous updates.

### Trade Simulator

When you save a strategy from the Strategy Builder, it lands in SQLite (`~/.market_analyzer/iv_history.db`, table `saved_positions`).

The Trade Simulator tab pulls all open positions and marks each one to market using a 3-tier data priority:

```
For each leg:
  1. Try WebSocket tick (sub-second)
     ↓ if not subscribed or stale
  2. Try NSE option chain (30s cache)
     ↓ if expiry/strike not found
  3. Fall back to Black-Scholes theoretical
```

The "Src" column in the legs table tells you which source priced each leg. WS = WebSocket, CHAIN = NSE, BS = Black-Scholes.

### IV Rank

Every time you visit the Strategy Builder tab during market hours, today's ATM IV is silently recorded to the SQLite database (idempotent — re-running updates the row).

After ~30 days of daily visits, the IV Rank widget shows:

- **IV Rank** = (today - 52w low) / (52w high - 52w low) × 100
- **IV Percentile** = % of days in the window with IV below today's
- **52w range** + mean
- A historical IV chart with today's IV and the mean overlaid
- An interpretation label (Very Low / Below Avg / Above Avg / Very High) with trade advice

**Why both rank and percentile?** Rank is intuitive ("near top or bottom"). Percentile is statistical ("how often has it been lower"). They diverge in skewed distributions — rank says "near top" if IV had one big spike; percentile reveals that's an outlier.

## Troubleshooting

| Problem | Fix |
|---|---|
| `ModuleNotFoundError: scipy` | `pip install scipy` |
| Strategy Builder tab errors out | Confirm all 8 .py files are in the same folder |
| Greeks show zeros | Chain returned IV = 0 — edit IV % in the leg row manually |
| IV Rank says "not enough data" | Normal for first ~30 days. Visit the tab daily during market hours. |
| Saved position MTM is stuck on entry prices | Chain stale or rate-limited. Use the refresh button. |
| Trade Simulator shows "BS" source for everything | Chain unavailable (market closed?) or WS not connected |
| `Port 5000 already in use` | Kill the conflicting process or change `redirect_port` in `KiteSession` (also update your Kite app redirect URL) |
| `RuntimeError: There is no current event loop` | KiteTicker uses Twisted. On Python 3.13, downgrade to 3.11/3.12. |
| WebSocket disconnects mid-day | Built-in auto-reconnect handles it. Check the Live Ticker tab's status row. |

## Database location

- `~/.market_analyzer/iv_history.db` — daily IV snapshots + saved positions
- `~/.kite_session.json` — Kite access token (mode 0600, owner-only)

Both files persist across reboots. Delete `iv_history.db` to start fresh; delete `.kite_session.json` to force re-login.

## Token security

- Session file `~/.kite_session.json` permissions are 0600 (owner-only)
- Tokens auto-invalidate at ~06:00 IST daily (Zerodha policy)
- The local HTTP server during login is open for the ~3-min login window then shuts down
- API Secret only used at exchange-time; never written to disk
