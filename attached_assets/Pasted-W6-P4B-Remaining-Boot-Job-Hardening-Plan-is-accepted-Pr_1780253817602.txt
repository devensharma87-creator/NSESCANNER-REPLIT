# Approved scope

Add a lightweight post-boot log that reports DB pool utilization from the existing pool object, if available.

Suggested metrics:

```text id="56brez"
pool total count
pool idle count
pool waiting count
pool max
timestamp / uptime
label
```

Use only in-memory pool counters if exposed by the existing DB pool library.

Do **not** execute a DB query just to collect metrics.

Do **not** acquire a DB connection.

Do **not** change pool config.

Do **not** add new dependency.

---

## Suggested timing

Schedule one or more read-only log snapshots after boot, for example:

```text id="lb2w8z"
30s after boot
75s after boot
120s after boot
```

If keeping it strictly one-time is cleaner, use:

```text id="q1poar"
120s after boot
```

Choose the simplest safe version and report exact timing.

The log should be low-noise and owner/operator-facing only.

# Preferred implementation shape

If current DB pool object supports it, create a helper such as:

```text id="fy2t35"
getDbPoolStats()
logDbPoolStats(label)
scheduleDbPoolStatsLog(label, delayMs)
```

Expected behavior:

* does not throw if pool stats are unavailable,
* logs unavailable state instead of crashing,
* never blocks server startup,
* never queries DB,
* never leaks secrets,
* never logs connection strings,
* fail-open.

If the DB pool is not accessible without risky changes, stop and report instead of forcing it.
