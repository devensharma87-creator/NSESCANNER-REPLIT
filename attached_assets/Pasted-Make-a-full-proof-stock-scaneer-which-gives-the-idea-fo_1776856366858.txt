Two important realities first:

There is no “foolproof” stock scanner. Any tool can improve decision quality, but it cannot guarantee profitable buy/sell calls.
A truly live, all-NSE, production-grade scanner depends heavily on licensed or reliable market data sources. NSE data, delivery %, block deals, shareholding, live quotes, and structured news are not all cleanly available from one free source.

So the best practical way is to build this in two layers:

• Layer 1: Core scanner engine using technical + financial + ownership + news scoring
• Layer 2: Live web app using Flask + HTML + JS auto-refresh

I’ll give you a working implementation blueprint and codebase that you can run and extend. I’ll also tell you where external APIs are needed.

My recommendation on architecture

Use this stack:

• Backend: Python + Flask
• Frontend: HTML + Bootstrap + JS
• Storage: SQLite initially, later PostgreSQL
• Scheduler: APScheduler / cron
• Live updates: polling every 30–60 seconds initially, later WebSocket
• Market data: start with yfinance for prototyping, then migrate to a proper NSE/live data vendor
• News: RSS/News API integration
• Financials / holdings: scraping/API layer
• Scanner engine: pandas-based factor scoring

Existing tools worth learning from

If you want a reference before building, PKScreener is one of the more feature-rich open-source NSE-focused scanners. Its repo describes 40+ scanners, Telegram alerts, backtesting, technical scans, and support for Nifty universes and even NASDAQ. It’s MIT-licensed, Python-based, and appears actively updated, with a latest release dated 2026-03-18. github.com togithub.com

Other open-source NSE scanners exist, but they’re generally narrower or older. For example, NSE-Stock-Scanner includes live-data ideas, backtesting, swing/intraday logic, and broker integration concepts, but its README also mentions bugs in live data refresh. github.com

A lightweight experimental project, NSEStockScanner, supports configurable indicators like EMA, RSI, MACD, BB, StochRSI, and rule-based signal definitions, but it’s much smaller and not close to the full platform you described. github.com

So my suggestion is:

• Do not reinvent everything from zero if speed matters.
• Build your dashboard/scoring layer around a clean architecture.
• Borrow ideas from PKScreener’s breadth, but create your own scoring and frontend.

Practical data-source reality

For a prototype:

• NSE symbol list: maintain CSV / scrape
• OHLCV: yfinance works as a prototype, but not ideal for NSE production/live
• Delivery %: likely from NSE bhavcopy / delivery files or broker/vendor feeds
• Block/bulk deals: NSE/BSE public disclosures
• Promoter/FII/DII holdings: screener-style public data, exchange filings, company shareholding patterns
• Financials: company filings / financial APIs / scraping
• News: NewsAPI, Google News RSS, or a news vendor

For production/live, you’ll probably need:
• broker API or market data vendor
• structured fundamentals vendor
• structured news feed

Core design of recommendation logic
Buy signal example
A stock is Buy when most of these align:

• Price > EMA20 > EMA50
• EMA20 crossed above EMA50 recently or spread widening
• RSI between 55 and 70
• Bullish candle structure / breakout above swing high
• Volume > 1.5x average volume
• Delivery % above recent mean
• Price above high-volume acceptance zone
• Positive or neutral recent news
• No major deterioration in 10–15 quarter trend
• Stable/improving promoter / FII pattern
• Positive block deal / institutional accumulation signals

Sell signal example
• Price < EMA20 < EMA50
• EMA20 below EMA50
• RSI below 45 or bearish divergence
• Breakdown below swing low / support
• High volume on down move
• Delivery % elevated on down move
• Negative news
• Weakening financial trend
• Falling institutional confidence
