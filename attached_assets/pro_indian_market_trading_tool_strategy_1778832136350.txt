01. EXECUTIVE SUMMARY
================================================================================

The platform should not be built as a normal indicator-based scanner. It should be built as an Indian Market Intelligence and Trading Decision Platform.

The goal is to answer five questions every trading day:

1. What is the current market regime?
2. Which side has institutional and derivative confirmation?
3. Which sectors are leading or weakening?
4. Which F&O trades are actually high probability today?
5. Which cash stocks are close to swing-tradeable levels?

A professional system should not generate random BUY/SELL alerts. It should generate only filtered, evidence-backed, risk-defined, backtested, and explainable signals.

The platform should have two major trading engines:

A. F&O Engine
Focused on NIFTY, BANKNIFTY, FINNIFTY, MIDCPNIFTY, NIFTYNXT50, and F&O stocks.
Primary focus: intraday and short-duration directional option trades.
Secondary focus: option-chain intelligence, OI, IV, PCR, straddle, expiry behaviour, and risk.

B. Swing Cash Engine
Focused on NSE cash stocks, especially NIFTY 500, liquid midcaps, F&O stocks, and high relative-strength names.
Primary focus: 5-20 session swing trades.
Secondary focus: sector rotation, stock relative strength, volume, delivery, breakouts, pullbacks, and risk-reward.

The foundation must be a strong data warehouse. Without reliable candles, instrument master, option-chain snapshots, sector data, corporate actions, and historical outcomes, the tool cannot become professional.

03. CURRENT SYSTEM DIRECTION BASED ON AUDIT
================================================================================

Based on the earlier database audit, the existing system has useful early components:

- F&O signal history
- Swing scanner history
- Paper trading tables
- FII/DII data
- Participant OI tables
- IV history
- Watchlists
- TradingView alert intake

But it has major gaps before it can be called pro-grade:

1. Historical candle data is missing or underdeveloped.
   A serious platform needs 1-minute, 3-minute, 5-minute, 15-minute, daily, weekly, and adjusted daily candles.

2. Indian instrument master is incomplete.
   The system needs NSE, BSE, F&O, index, sector, lot size, tick size, expiry, and contract metadata.

3. F&O signals need stronger option-chain context.
   A signal without OI, PCR, IV, spread, liquidity, expiry, and straddle context is incomplete.

4. Swing signals need sector and lifecycle logic.
   A swing tool should know whether a stock is a sector leader, near trigger, triggered, invalidated, active, or closed.

5. Backtesting is not yet sufficient.
   Confidence should not be a static label. It should come from historical expectancy.

6. Security needs improvement.
   API/session credentials should never be included in portable database backups.

06. KITE API ARCHITECTURE
================================================================================

Kite API should be used carefully and professionally. Do not build a system that keeps hitting REST APIs unnecessarily during market hours.

--------------------------------------------------------------------------------
06.1 Daily Pre-Market Process
--------------------------------------------------------------------------------

Before market open:

1. Fetch full instrument master.
2. Store instrument master snapshot.
3. Update current contracts.
4. Update expiry calendar.
5. Update lot sizes and strike list.
6. Build index watchlist.
7. Build F&O active contract watchlist.
8. Build swing watchlist.
9. Mark stale/expired instruments inactive.
10. Prepare WebSocket subscription lists.

--------------------------------------------------------------------------------
06.2 Live Market Process
--------------------------------------------------------------------------------

During market hours:

1. Use WebSocket for live ticks.
2. Subscribe to indices, major F&O instruments, active ATM/near-ATM options, and watchlist stocks.
3. Build 1-minute candles from ticks.
4. Reconcile with official/historical data later.
5. Capture option-chain snapshots every 1-5 minutes depending on priority.
6. Run F&O engine every 1, 3, or 5 minutes.
7. Run swing trigger engine every 5 or 15 minutes.
8. Push only actionable alerts.

--------------------------------------------------------------------------------
06.3 End-of-Day Process
--------------------------------------------------------------------------------

After market close:

1. Finalize candles.
2. Reconcile candles with historical source.
3. Store end-of-day bhavcopy data.
4. Update delivery data.
5. Update sector strength.
6. Mark F&O signal outcomes.
7. Mark swing signal outcomes.
8. Update backtest metrics.
9. Generate next-day watchlist.
10. Prepare pre-market levels.

--------------------------------------------------------------------------------
06.4 Suggested WebSocket Grouping
--------------------------------------------------------------------------------

Connection 1:
- NIFTY
- BANKNIFTY
- FINNIFTY
- MIDCPNIFTY
- NIFTYNXT50
- India VIX
- major indices
- top F&O stocks

Connection 2:
- active option contracts
- ATM, ITM, and OTM strikes
- current and next expiry contracts

Connection 3:
- swing watchlist
- high-priority cash stocks
- high-volume breakout candidates

--------------------------------------------------------------------------------
06.5 Kite API Handling Rules
--------------------------------------------------------------------------------

- Do not expose API secret in frontend.
- Do not store access tokens in plain text.
- Rotate leaked or exported credentials.
- Use backend-only authentication.
- Batch API requests.
- Cache quote snapshots.
- Use WebSocket for live data.
- Store instrument master daily.
- Use retry with backoff.
- Maintain API health dashboard.
- Log every failed request.

08. F&O SIGNAL SCORING SYSTEM
================================================================================

Every F&O signal should get a 100-point score.

Recommended model:

1. Market Regime - 15 points
2. Trend Structure - 15 points
3. Futures OI Confirmation - 15 points
4. Option Chain Confirmation - 20 points
5. Liquidity and Spread - 10 points
6. IV/VIX Condition - 10 points
7. Risk-Reward - 10 points
8. Historical Expectancy - 5 points

Signal category:

- 90 to 100: A+ Signal
- 80 to 89: A Signal
- 70 to 79: Conditional Watch
- Below 70: No Trade

Do not show "High Conviction" unless:
- historical expectancy is positive
- minimum number of similar past trades exists
- risk-reward is valid
- spread is acceptable
- OI and price confirmation agree
- market regime supports the setup

Suggested minimum requirements for a tradable F&O signal:

- score >= 80
- risk-reward >= 1:1.5
- spread <= allowed threshold
- volume above minimum threshold
- signal not generated during no-trade window
- option premium stop loss available
- spot invalidation level available
- historical sample size available

09. F&O ENTRY AND EXIT STRATEGY FRAMEWORK
================================================================================

--------------------------------------------------------------------------------
09.1 Strategy 1: Index Momentum Breakout
--------------------------------------------------------------------------------

Best for:
- strong trending days
- first half of trading session
- clear institutional/derivative confirmation

Bullish conditions:

- index above VWAP
- index above CPR
- price breaks opening range high
- futures price up + OI up
- put writing visible below spot
- call unwinding at resistance or call OI shifting higher
- ATM/ITM call has good volume
- spread acceptable
- India VIX not sharply rising against the trade
- breadth supports the move

Entry:

- buy ATM or slightly ITM CE above confirmed breakout
- or buy after pullback to breakout zone if breakout candle is too large

Stop loss:

- option premium SL
- spot SL below breakout zone/VWAP/opening range
- time-based SL if no movement after defined period

Targets:

- target 1 at 1R or nearest resistance
- target 2 at 2R or next OI resistance
- trail after target 1

Exit:

- partial exit at target 1
- trail remaining quantity
- exit if spot closes below VWAP
- exit if OI confirmation reverses
- exit if option spread widens abnormally
- exit before end-of-day cutoff

Bearish conditions:

- index below VWAP
- index below CPR
- price breaks opening range low
- futures price down + OI up
- call writing visible above spot
- put unwinding at support or put OI shifting lower
- ATM/ITM put has good volume
- breadth weak

Entry:

- buy ATM or slightly ITM PE below confirmed breakdown

Stop loss:

- option premium SL
- spot SL above breakdown zone/VWAP/opening range

--------------------------------------------------------------------------------
09.2 Strategy 2: Pullback Continuation
--------------------------------------------------------------------------------

Best for:
- trend days where initial breakout is missed

Bullish setup:

- market regime bullish
- price above VWAP
- price above 20 EMA
- pullback to VWAP/20 EMA/demand zone
- low-volume pullback
- put writing remains intact
- futures OI does not collapse
- reversal candle confirms

Entry:

- buy CE after reversal candle high breaks

Stop loss:

- below pullback low
- option premium stop loss

Exit:

- trail using 9 EMA or VWAP
- exit if price closes below VWAP
- exit if OI support breaks

Bearish setup:

- market regime bearish
- price below VWAP
- price below 20 EMA
- pullback to VWAP/supply zone
- call writing remains intact
- reversal candle confirms

Entry:

- buy PE after rejection candle low breaks

--------------------------------------------------------------------------------
09.3 Strategy 3: Range Day / Expiry Day Avoidance
--------------------------------------------------------------------------------

Best use:
- protect option buyers from theta decay and false signals

Range day signs:

- price stuck inside previous day range
- repeated VWAP mean reversion
- weak ADX
- low directional breadth
- OI walls on both call and put side
- ATM straddle decaying
- no clean sector leadership
- false breakouts on both sides

Recommended output:

- Market Type: Range
- Action: Avoid option buying
- Trade only edge reversals if system supports it
- Prefer no-trade for retail users

This engine should save users from unnecessary trades.

--------------------------------------------------------------------------------
09.4 Strategy 4: Event / Volatility Engine
--------------------------------------------------------------------------------

Use when:

- RBI event
- Budget
- election result
- major gap
- global crash/rally
- sudden VIX spike
- major news event
- weekly/monthly expiry volatility

Output options:

- No Trade
- Wait for first 30 minutes
- Trade only after range confirmation
- Reduce position size
- Avoid far OTM options
- Use strict SL

--------------------------------------------------------------------------------
09.5 Option Selection Logic
--------------------------------------------------------------------------------

For option buying:

Prefer:
- ATM options
- slightly ITM options
- high liquidity
- low spread
- strong volume
- acceptable IV
- strong delta

Avoid:
- far OTM lottery options
- illiquid strikes
- wide spreads
- low volume
- contracts close to expiry without momentum
- buying high IV after large move unless momentum is very strong

--------------------------------------------------------------------------------
09.6 F&O Invalidation Logic
--------------------------------------------------------------------------------

Every signal must have invalidation.

Examples:

Bullish CE invalidation:
- spot closes below VWAP
- put writing unwinds
- futures OI collapses
- call side resistance becomes stronger
- option premium breaks SL
- market breadth turns negative

Bearish PE invalidation:
- spot closes above VWAP
- call writing unwinds
- futures short buildup reverses
- put side support strengthens
- option premium breaks SL
- market breadth recovers

10. SWING TRADING ENGINE
================================================================================

The swing engine should be built around:

Sector Rotation + Relative Strength + Price-Volume Confirmation + Risk-Reward

It should not simply scan RSI or moving average crossovers.

Recommended swing flow:

1. Check market regime.
2. Rank sectors.
3. Rank stocks inside strong sectors.
4. Check relative strength vs NIFTY.
5. Check relative strength vs sector.
6. Identify breakout, pullback, or reversal setups.
7. Confirm volume and delivery.
8. Check risk-reward.
9. Check event risk.
10. Generate watchlist or buy trigger.

--------------------------------------------------------------------------------
10.1 Swing Universe
--------------------------------------------------------------------------------

Recommended universe:

- NIFTY 50
- NIFTY 100
- NIFTY 200
- NIFTY 500
- all F&O stocks
- high liquidity midcaps
- sector leaders
- stocks with average daily traded value above threshold

Avoid:

- illiquid stocks
- ASM/GSM risky stocks unless explicitly marked
- stocks near bad corporate event
- stocks with very low delivery/traded value
- penny stocks
- stocks with abnormal circuit risk

--------------------------------------------------------------------------------
10.2 Swing Setup Types
--------------------------------------------------------------------------------

A. Breakout Swing
B. Pullback Swing
C. Reversal Swing
D. Base Formation Swing
E. Sector Leader Continuation
F. Post-Earnings Momentum
G. Relative Strength Breakout

11. SWING SIGNAL SCORING SYSTEM
================================================================================

Every swing signal should get a 100-point score.

Recommended model:

1. Market Regime - 10 points
2. Sector Strength - 15 points
3. Stock Relative Strength - 15 points
4. Price Structure - 15 points
5. Volume and Delivery - 15 points
6. Momentum - 10 points
7. Fundamental Quality - 10 points
8. Risk-Reward - 5 points
9. Event/Corporate Action Safety - 5 points

Action classification:

- 85+ and trigger hit: BUY NOW
- 75 to 84 and near trigger: HIGH PRIORITY WATCH
- 65 to 74: WATCHLIST
- 55 to 64: WAIT
- Below 55: AVOID

Important rule:
The score and action must not contradict each other. If a stock has score 80 but action says AVOID, the system must clearly explain the reason, such as low liquidity, event risk, bad risk-reward, or weak sector.

12. SWING ENTRY AND EXIT STRATEGY FRAMEWORK
================================================================================

--------------------------------------------------------------------------------
12.1 Strategy 1: Sector Leader Breakout
--------------------------------------------------------------------------------

Best for:
- strong market regime
- sector rotation
- institutional accumulation

Conditions:

- sector in top 3 or top 5
- stock outperforming NIFTY
- stock outperforming its sector
- price near 20-day/50-day/52-week breakout
- volume above 1.5x or 2x average
- delivery percentage improving
- clean base formation
- risk-reward at least 1:2

Entry:

- buy above breakout level
- or buy on retest if breakout already happened

Stop loss:

- below breakout base
- below recent swing low
- ATR-based stop for volatile stocks

Targets:

- target 1 = 1.5R
- target 2 = 2.5R or 3R
- trail remaining quantity with 10 EMA or 20 EMA

Exit:

- close below 20 EMA
- breakdown below swing low
- high-volume reversal
- sector weakness
- target achieved
- earnings/event risk

--------------------------------------------------------------------------------
12.2 Strategy 2: Pullback in Uptrend
--------------------------------------------------------------------------------

Conditions:

- stock in confirmed uptrend
- sector strong
- price above 50 DMA or 200 DMA
- pullback to 20 EMA/50 EMA/demand zone
- low-volume pullback
- reversal candle appears
- RS remains strong

Entry:

- buy above reversal candle high
- or buy near support with confirmation

Stop loss:

- below pullback low

Exit:

- target previous high
- trail if breakout follows

--------------------------------------------------------------------------------
12.3 Strategy 3: Reversal Swing
--------------------------------------------------------------------------------

This should be used with lower position size.

Conditions:

- stock oversold
- positive divergence
- capitulation volume
- price reclaims key moving average
- sector stops falling
- market regime stabilizes

Entry:

- buy above reversal confirmation

Stop loss:

- below recent low

Risk:
Reversal trades fail more often than continuation trades. The system should clearly label them as high risk.

--------------------------------------------------------------------------------
12.4 Swing Invalidation
--------------------------------------------------------------------------------

Swing trade should be invalidated if:

- price closes below stop
- sector rank collapses
- relative strength breaks down
- breakout fails within 2-3 sessions
- volume dries after breakout
- market regime turns bearish
- negative corporate event appears
- risk-reward becomes poor

15. RISK MANAGEMENT ENGINE
================================================================================

A professional tool must control risk before generating a trade.

--------------------------------------------------------------------------------
15.1 Universal Risk Rules
--------------------------------------------------------------------------------

- max risk per trade
- max risk per day

15.4 Position Sizing Formula
--------------------------------------------------------------------------------

For swing:

Capital risk per trade = Total capital x Risk percentage

Quantity = Capital risk per trade / (Entry price - Stop loss)

Example:

Capital = Rs. 500,000
Risk per trade = 1%
Capital risk = Rs. 5,000
Entry = Rs. 500
Stop = Rs. 475
Risk per share = Rs. 25
Quantity = 5000 / 25 = 200 shares

For F&O:

Risk should be calculated using option premium SL and lot size.

Loss per lot = (Entry premium - SL premium) x lot size

Allowed lots = Max risk per trade / Loss per lot

The following official references should be used while implementing the system:

1. Kite Connect Market Quotes
   Key implementation note:
   The quote API can provide full market snapshots including OHLC, OI, and market depth. Use this for snapshots, not high-frequency polling.

2. Kite Connect Historical Data
   Key implementation note:
   Historical candle data supports multiple intervals and can include OI where available. Use it for reconciliation and backfilling.

3. Kite Connect WebSocket
   Key implementation note:
   WebSocket is the right approach for live data. Kite supports live quote streaming with subscription limits per connection and API key.

4. NSE Equity Derivatives Contract Specifications
   Key implementation note:
   Expiry handling must be dynamic. Do not hardcode old expiry assumptions. Use exchange contract files and expiry calendar logic.
