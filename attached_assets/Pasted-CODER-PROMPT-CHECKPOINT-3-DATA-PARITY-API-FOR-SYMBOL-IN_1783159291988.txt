CHECKPOINT 3 OBJECTIVE
====================================================

Build a production-safe Data Parity API that proves whether the same symbol/index is using the same market data across the website.

A stock/index must have one canonical OHLC/quote truth across the app.

- INDUSINDBK should not show one price in Paper Trading and another in Scanner.

This checkpoint is diagnostic-first.

It must detect and report mismatches clearly.

PHASE 1 — DEFINE DATA PARITY CONTRACT
====================================================

Create a strict data parity result contract.

Suggested types:

```ts
type DataParitySeverity = "P0" | "P1" | "P2" | "INFO";

type DataParityModule =
  | "CANONICAL_QUOTE"
  | "SCANNER"
  | "WATCHLIST"
  | "PORTFOLIO"
  | "PAPER_TRADING_EQ"
  | "SWING_QUEUE"
  | "CHARTING"
  | "STOCK_INTELLIGENCE"
  | "FNO_DIAGNOSTICS"
  | "OPTION_CHAIN"
  | "PRE_MARKET_REPORT"
  | "POST_MARKET_REPORT"
  | "GLOBAL_DATA_HEALTH";

type DataParityObservation = {
  module: DataParityModule;
  symbol: string;
  canonicalKey: string | null;
  ltp: number | null;
  open: number | null;
  high: number | null;
  low: number | null;
  close: number | null;
  previousClose: number | null;
  change: number | null;
  changePct: number | null;
  source: string | null;
  sourceAsOf: string | null;
  freshnessSec: number | null;
  tradeGrade: boolean;
  reportGrade: boolean;
  canDriveSignals: boolean;
  canDrivePaperTrades: boolean;
  canDriveReports: boolean;
  status: "AVAILABLE" | "MISSING" | "STALE" | "NOT_APPLICABLE" | "ERROR";
  reason: string | null;
};

type DataParityMismatch = {
  severity: DataParitySeverity;
  field: string;
  modules: string[];
  expected: string | number | null;
  actual: Array<{ module: string; value: string | number | null }>;
  reason: string;
  recommendedAction: string;
};

type DataParityResult = {
  symbol: string;
  canonicalKey: string | null;
  checkedAt: string;
  observations: DataParityObservation[];
  mismatches: DataParityMismatch[];
  verdict: "PASS" | "P0_MISMATCH" | "P1_MISMATCH" | "P2_MISMATCH" | "INSUFFICIENT_DATA";
};

PHASE 2 — MISMATCH CLASSIFICATION RULES

Implement clear mismatch rules.

P0 mismatch:

Same symbol has different LTP between trade-grade modules using same source/as-of.
Same symbol has different daily OHLC for same date.
A stale/proxy/display/report-grade quote is marked trade-grade.
Yahoo/cache/report-grade data can drive signals.
Yahoo/cache/report-grade data can drive paper trades.
Paper Trading uses a quote different from canonical trade-grade source.
F&O diagnostics uses non-canonical or stale trade-driving data.
Same index close differs between pre/post-market report and canonical report-grade source.

P1 mismatch:

Source label missing.
Source as-of missing.
Freshness missing.
Module uses direct provider path but value matches canonical.
Module uses cache without label.
Report-grade/trade-grade distinction unclear.
Symbol identity differs but value is same.

P2 mismatch:

Formatting difference.
Rounding difference within tolerance.
Display name mismatch.
Non-critical stale display-only module clearly labelled.

INFO:

Module not applicable.
Market closed.
No active trade for that symbol.
Swing staged-only, no paper trade by design.
