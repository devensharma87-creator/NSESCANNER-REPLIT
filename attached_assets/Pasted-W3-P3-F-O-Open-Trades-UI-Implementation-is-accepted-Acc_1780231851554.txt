# UI requirements

## 1. Main headline

Show:

```text id="1ec8dv"
Official P25 Evidence: N/20
Remaining: 20 - N
Gate: OPEN / THRESHOLD MET
```

Use color/badge:

* OPEN = amber,
* THRESHOLD MET = green,
* unavailable = neutral.

## 2. Evidence math section

Show:

* official eligible count,
* threshold,
* remaining,
* raw rows,
* processed rows,
* excluded 0/0 rows if available/derivable,
* low-sample warning.

Important:

If endpoint provides `rawRowCount`, `processedRowCount`, and `mfeAvailableCount`, derive:

```text id="f8eatw"
excludedPotential = processedRowCount - mfeAvailableCount
```

Label it carefully as:

```text id="86v0sx"
Excluded / not MFE-available rows
```

Do not overclaim that all excluded rows are definitely 0/0 unless the endpoint explicitly provides that breakdown.

## 3. Breakdown tables

If data exists, show compact breakdown tables for:

* index,
* setup,
* tier.

Columns should include only available fields such as:

* name,
* trade count,
* eligible count,
* P&L,
* average MFE,
* average MAE,
* win/loss,
* sample count.

Use flexible rendering based on actual endpoint shape.

No crash if a field is missing.

## 4. Explanation box

Add simple explanation:

```text id="kc77g0"
A trade counts for P25 only when it is closed, has valid exit premium, valid entry premium, valid quantity, and real MFE/MAE movement. 0/0 placeholder rows do not count.
```
