STAGE 3 — TRUSTED EXECUTABLE RESOLUTION

Remove all bare-command spawning.

Do not use:

- `spawn("vitest", ...)`;
- inherited PATH;
- `node_modules/.bin/vitest` passed to Node without verifying its file type;
- a hard-coded path that assumes a specific package-manager layout.

Required design:

1. Resolve the installed Vitest package through Node/package module resolution.
2. Read the installed package metadata and its authoritative `bin` entry.
3. Resolve and canonicalize the actual JavaScript CLI entry.
4. Resolve and canonicalize `process.execPath`.
5. Verify the CLI:
   - exists;
   - is a regular file;
   - is an expected JavaScript module type;
   - remains within the canonical installed Vitest package directory.
6. Use `path.relative()` containment checks. Do not use string `startsWith()` for path containment.
7. Fail closed if resolution, canonicalization, metadata validation or containment fails.
8. Spawn:

   canonical Node executable
   + canonical Vitest JavaScript CLI
   + explicit Vitest arguments

9. Set `shell: false`.
10. Do not include PATH in the child environment.

Do not assume `.bin/vitest` is JavaScript. Inspect the installed package and use its real CLI target.

- XDG_CONFIG_HOME beneath that root;
- XDG_CACHE_HOME beneath that root;
- XDG_DATA_HOME beneath that root;
- XDG_RUNTIME_DIR beneath that root.

Requirements:

4. Do not use TEST_RUN_ID as the only uniqueness mechanism.
5. Set restrictive directory permissions where supported.
6. Create all required subdirectories explicitly.
7. Never inherit parent HOME, PATH, TMPDIR, TMP, TEMP or XDG paths.
8. Return an explicit run-context object containing:
   - canonical run root;
   - isolated HOME;
   - isolated temp path;
   - XDG paths;
   - child environment;
   - resolved executable information.

Keep filesystem creation separate from the pure child-environment builder where practical, so pure policy behaviour remains independently testable.

STAGE 8 — SAFE CLEANUP

Clean exactly one generated run root after the child exits or spawn fails.

Required safety invariants:

1. Canonicalize the OS temporary parent.
2. Inspect the generated root using `lstat`.
3. Refuse cleanup if the root is a symbolic link.
4. Require a directory.
5. Canonicalize the generated root.
6. Use `path.relative(canonicalTempParent, canonicalRunRoot)`.
7. Reject cleanup when:
   - the relative path is empty;
   - it is absolute;
   - it begins with `..`;
   - it contains more than one path segment;
   - its basename does not begin with the fixed safe prefix.
8. Do not rely on:
   - `startsWith()` containment;
   - `includes(TEST_RUN_ID)`;
   - an unresolved path;
   - a parent-provided path.
9. Delete only the single validated generated run root.
10. If validation fails, refuse deletion and surface an explicit cleanup safety error.
11. Cleanup must occur on:
   - normal child close;
   - non-zero exit;
   - child error;
   - synchronous spawn failure.
12. Ensure cleanup executes at most once.

Do not run destructive shell commands. Cleanup must use the narrowly validated Node filesystem path created by this process.

Document the remaining local filesystem race limitations honestly; do not claim OS-level sandboxing.
