# W6-P4A: Scheduler Boot Staggering Only

Purpose:

Reduce cold-start background-job pile-up by staggering background job startup timing.

This is a low-risk hardening change.

Do not change trading logic.

Do not change paper execution.

Do not change DB schema.

Do not change DB pool size.

Do not change scheduler frequency/cadence after startup.

Do not change env/secrets.

Do not change auth.

---

## Approved scope

Implement only boot-time staggering for existing background subsystems so they do not all start in the same cold-start window.

Known boot subsystems from W6-P3/W6-P4:

```text id="mc907i"
startGlobalDataPump()
startScreenerPresetScheduler()
instFlows self-scheduler / participant OI boot tick
```

Goal:

```text id="b4tj0n"
Avoid all heavy background jobs hitting the shared 10-connection DB pool immediately at boot.
```

---

## Allowed behavior change

Allowed:

* delay/stagger initial startup of background jobs,
* add small deterministic boot offsets,
* add clear startup logs showing stagger timing,
* keep each job fail-open,
* keep existing periodic intervals unchanged after startup.

Not allowed:

* changing 30s preset scheduler frequency,
* changing 15-min participant-OI interval,
* changing OI lookback window,
* disabling jobs,
* changing DB pool,
* adding a new DB pool,
* changing Yahoo/Kite timeout behavior,
* changing trading/paper-exec logic.

---

## Preferred implementation shape

Use a small, simple, testable helper if useful, for example:

```text id="6ceh35"
scheduleBootJob(label, delayMs, fn)
```

The helper should:

* log scheduled delay,
* run the job after delay,
* catch/log errors,
* preserve fail-open behavior,
* not block API server startup,
* not crash the app if the job fails.

Suggested boot spacing:

```text id="jlh9ig"
0–5 seconds: lightweight app/server boot only
10–20 seconds: global data pump
25–40 seconds: preset scheduler first tick
45–75 seconds: participant OI / instFlows initial tick
```

Exact values can differ if existing code structure requires it, but they must be clearly reported.
