Do not hide this logic in backend.

Everything is client-side only.

## 2. Filtering behavior

Apply filters to combined trade rows where safe.

For open trades:

* status = OPEN,
* no exit reason,
* no exit date,
* realised P&L unavailable,
* unrealised P&L available.

For closed trades:

* status = CLOSED,
* exit reason available if payload has it,
* realised P&L available,
* unrealised P&L unavailable.

If a filter cannot apply to a row because data is missing, handle safely.

No crash.

No mutation.

## 3. Sorting behavior

Allow sorting by:

* entry time,
* exit time,
* realised P&L,
* unrealised P&L,
* MFE,
* MAE,
* time in trade,
* index/symbol.

Use existing `sortFoRows`.

Null/NaN values last.

Do not mutate input rows.

## 4. Grouping behavior

Allow grouping by:

* none,
* index,
* setup,
* exit reason,
* status,
* P25 status,
* P&L sign.

Use existing `groupFoRows`.
