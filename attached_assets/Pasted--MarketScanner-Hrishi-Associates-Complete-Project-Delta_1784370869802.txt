**Damage window**: ~54 minutes of dropped INSERTs (10:50–11:43 IST). Reasoning

### 1.4 VIX-corruption (P1 · numerically proven, fix DEFERRED to M3 rider)

**Discovery**: Phase 0 Data Availability Matrix Row C probe found
`fno_signal_reasoning.vix` last-48h distribution = 30 NULLs + 6 negatives (–4.80 to
–4.51). Full-table scan showed 109 NULLs + 32 non-nulls, all non-nulls being
change-percent values rather than VIX levels.

**Root cause (fully diagnosed 2026-07-16)**: `optionSignals.ts:3191` passes
`gateCtx.vix.intradayPct` (a change-%) into a level-typed field. `VixSnapshot`
interface at `optionSignalGates.ts:80–89` has only percent fields (`intradayPct`,
`dayPct`, `spike`, `reason`) — no `.level` field exists on the struct. Bug is
architectural at the type level.

**Fix shape (queued as rider on M3 PAPER_WRITER-DISCIPLINE)**:
1. Add `level: number | null` to `VixSnapshot`.
2. Populate `.level` in `loadVixSnapshot()` from the same Kite quote that already
   feeds `intradayPct`.
3. Change writer line to pass `.level` not `.intradayPct`.
4. Sanity gate at write time: reject writes outside 5..80.
5. VIX-unavailable case (109 NULLs half of the pattern): explicit NULL with
   `data_quality` annotation on the row.

**Denominator ruling for the fix's acceptance query**: post-cutover rows only
(writer_version stamped by the fix onward). Historical rows stay dirty per
no-retro-mapping ruling.

**Not landing tonight per owner sequence discipline.** Rider ships with M3.

### 2.2 `run_postgres.sh` self-heal binary-check fix (2026-07-17)

**File**: `/app/scripts/env/run_postgres.sh`

**Root cause of the defect it prevents**: the old `PGBIN` glob
(`ls -d /usr/lib/postgresql/*/bin`) checked for the directory's existence, not the
`postgres` binary itself. When only `postgresql-client-15` was preserved (the exact
container-recycle state on 2026-07-17), `bin/` existed with client tools but no
server binary — script skipped its install branch in an infinite loop until
supervisor FATAL'd.

**Fix**: `find_pgbin()` helper that iterates `bin/` candidates and returns the newest
one that actually contains the `postgres` executable. Same helper is used at both
call sites in the script (pre-install check + post-install re-check).

**Dry-run evidence pack**: 4 cases (current healthy state / synthetic client-only
state / synthetic multi-version / synthetic fresh-pod) — all pass. Case B is the
direct reproduction proving the change would have prevented the morning's
90-minute incident.

**Next container recycle no longer punishes delay.**
