## A. AUTHORIZED OBJECTIVE

Prove that a clean API-server process can restore the latest compatible Schema-5 authoritative instrument registry from the development PostgreSQL durable store before any consumer relies on registry coverage.

Boot restoration must:

* Read the latest compatible Schema-5 generation.
* Verify its stored checksum and record-set integrity.
* Verify the embedded calendar commitment.
* Re-evaluate calendar and BSE authority at the actual boot time.
* Restore the exact generation identity and record count without rebuilding it.
* Make the restored registry available to the coverage bridge and data-health surfaces.
* Distinguish data integrity from current authority.
* Fail closed when the generation is missing, incompatible, corrupt, expired or unverifiable.
* Perform zero provider subscriptions.
* Perform zero registry/database writes.
* Keep all safety locks disabled.

This phase does not require the restored generation to be currently authoritative. If the stored BSE authority has expired at midnight IST, the correct runtime result is `LAST_KNOWN`, `STALE` or the existing equivalent—not a fabricated authoritative state.

## D. REQUIRED BOOT CONTRACT

The registry boot state must be explicit and deterministic. Reuse existing names where equivalent states already exist.

Expected outcomes must distinguish:

* `RESTORED_CURRENT`
* `RESTORED_LAST_KNOWN`
* `NOT_CONFIGURED`
* `INCOMPATIBLE_SCHEMA`
* `CHECKSUM_MISMATCH`
* `CALENDAR_COMMITMENT_INVALID`
* `AUTHORITY_EXPIRED`
* `DATABASE_UNAVAILABLE`
* `RESTORE_FAILED`

Do not create duplicate status vocabularies unnecessarily.

A generation may enter the in-memory registry only when:

1. Schema version is exactly supported.
2. Policy versions are supported.
3. Stored payload parses successfully.
4. Payload checksum matches.
5. Record-set hash and count reconciliation pass.
6. Embedded calendar commitment verifies.
7. Generation identity matches its committed content.

Current authority must then be evaluated separately:

* Integrity valid + current authority valid → current authoritative state.
* Integrity valid + authority expired → last-known/stale state.
* Integrity invalid → do not install as trusted registry.
* No compatible generation → not configured/fail closed.
* Database failure → unavailable/fail closed.

Never change a stored checksum or generation identity during restoration.

## E. BOOT ORDERING

The restored registry must be installed—or restoration must reach an explicit terminal failure state—before any consumer can claim:

* authoritative universe coverage;
* complete market-data coverage;
* trade-grade readiness;
* scanner-universe authority;
* subscription-denominator authority.

Provider startup is outside this phase and must remain disabled for the controlled proof.

If existing application startup allows consumers to race ahead of restoration, correct the sequencing using the smallest existing startup mechanism. Do not add arbitrary sleeps, polling loops or new schedulers.

A restoration failure must not crash unrelated informational API availability unless the existing contract requires it. It must instead expose an honest unavailable/blocker state.

## F. NO-WRITE GUARANTEE

Boot restoration must be read-only.

Before and after the controlled boot, capture from the development database:

* total registry snapshot count;
* latest snapshot ID;
* latest generation ID;
* schema version;
* validation result;
* saved timestamp.

The values must remain identical.

Audit the boot restoration path for:

* `INSERT`
* `UPDATE`
* `DELETE`
* `TRUNCATE`
* `ALTER`
* `CREATE`
* retention calls
* source refresh calls
* registry rebuild calls

A schema-ensure or `CREATE TABLE IF NOT EXISTS` operation is still a database write and is not authorized for this proof.

If the current loader necessarily performs DDL or another write, stop and report:

`PHASE_0_7B_BLOCKED — BOOT_RESTORE_PATH_IS_NOT_READ_ONLY`

Do not execute it merely because it is idempotent.
