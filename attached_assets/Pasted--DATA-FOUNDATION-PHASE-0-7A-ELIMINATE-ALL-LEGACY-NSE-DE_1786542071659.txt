This phase is about identity correctness only. It does not expand live subscriptions or modify market-data values.

## E. CORRECT IDENTITY CONTRACT

The corrected path must use the existing exchange-qualified runtime identity and Schema-5 authoritative registry.

Preferred resolution order:

1. Existing valid `canonicalInstrumentId`
2. Exact provider instrument token mapped to one canonical identity
3. Exact exchange plus exact trading symbol or official security identifier
4. Explicit ambiguity or unavailable blocker

Never resolve by:

* Bare trading symbol alone when multiple candidates exist
* Defaulting a missing exchange to NSE
* Choosing the first search result
* Fuzzy symbol matching
* ISIN-deduplicating NSE and BSE listings
* Reconstructing a provider token
* Guessing from suffix or UI route
* Substituting a neutral or zero value

Cross-listed instruments remain separate:

* `NSE:EQUITY:<symbol>`
* `BSE:EQUITY:<symbol>`

They have separate order books and must never collapse merely because symbol or ISIN matches.
