# Goal

Prevent global scanner DB timeout failures from crashing the shared `api-server` process.

The global scanner may degrade, stale, or log warnings, but it must not crash:

```text id="b8xgdu"
api-server
F&O paper trader
equity paper trader
NSE scanner
candle warehouse
option snapshots
paper reports
```

# Accepted root cause

The accepted crash mechanism is:

```text id="aq7b4q"
Recurring global scanner timers dispatch async refreshers using bare void calls.
A DB timeout rejection can escape.
There is no safe catch boundary at the interval dispatch.
Node treats unhandled rejection as fatal.
The whole api-server exits with status 1.
```

Affected areas include:

```text id="xsnzcu"

```

Also review the latent same-class boundary in:

```text id="tvym4w"

tick

```

# Implementation scope

## 1. Guard recurring scheduler boundaries

Replace unsafe interval dispatches like:

```text id="mg8k6h"
void refreshBinance()
void fn()
void tick()
void runOne(...)
```

with safe dispatch wrappers that:

```text id="tvxz4c"
attach .catch()
log structured warning/error
do not throw
allow next interval to continue
do not change interval cadence
do not block the event loop
```

Do not change the scheduler timing.

Do not change refresh frequency.

---

## 2. Make global scanner DB helpers fail-soft

Ensure these helper failures cannot escape and crash the process:

```text id="o3dapy"
loadDisabledSet
upsertLivePrice
recordLivePriceError
recordTransientUpstreamError
recordSyncOk
recordSyncErr
seedGlobalUniverse if applicable
```

Expected behavior:

```text id="dw698x"
DB timeout in global scanner = log warning + mark/stale/failure count if possible + continue
DB timeout while recording failure = log compact warning + continue
No thrown rejection escapes refresher boundary
```

Important:

```text id="duzwiu"
If the failure-recording write itself fails, do not let that secondary failure crash the process.
```

---

## 3. Keep boot behavior intact

The boot call is already guarded.

Do not redesign boot.

Do not change boot staggering.

Only ensure recurring timer cycles are guarded.

---

## 4. Preset scheduler boundary

Review `presetScheduler.ts` for the same unsafe promise-dispatch pattern.

Add the same style of boundary protection if needed.

Do not change scheduler cadence or task selection.
