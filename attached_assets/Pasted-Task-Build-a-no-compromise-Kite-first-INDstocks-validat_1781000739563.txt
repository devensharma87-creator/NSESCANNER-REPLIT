Task: Build a no-compromise, Kite-first, INDstocks-validated market data architecture for Hrishi Associates Market Scanner.

I do not want any risk with market data. Wrong data is worse than no data. Do not patch the UI. Fix the actual data architecture.

Current confirmed problem:
The Watchlist tab was using a separate Yahoo-based path while the main scanner already had working Kite-first market data. This caused baskets to show 0 stocks or partial stale rows. That kind of broken parallel data path is unacceptable.

Project stack:
This is a TypeScript / React / Express project. Trace the real codebase. Do not follow old Python/app.js assumptions blindly.

Main data policy:

1. Kite is the PRIMARY source of truth for all market price data.
2. INDstocks may be added as SECONDARY / VALIDATION / FAILOVER provider after proof-of-data-quality.
3. Yahoo must not be used for production market prices unless explicitly enabled as low-trust delayed fallback.
4. Synthetic/mock data is forbidden in production.
5. Every row must expose source, asof, freshness, stale status, and warning flags.
6. Any provider mismatch must be visible. Do not silently choose random data.
7. Do not place live orders. This website remains scanner / analytics / paper-trading unless the owner explicitly approves trading APIs separately.

Important docs to read and implement against:

2. Provider source policy

Implement config:

MARKET_DATA_POLICY=KITE_PRIMARY_INDSTOCKS_VALIDATE

ENABLE_YAHOO_FALLBACK=false in production
ALLOW_SYNTHETIC_DATA=false in production
STRICT_DATA_FRESHNESS=true
STRICT_PROVIDER_MISMATCH=true

Rules:

* If Kite returns valid fresh data, use Kite.
* If INDstocks is enabled, use it for validation/cross-checking, not as silent replacement.
* If Kite fails and INDstocks succeeds, use INDstocks only if:

  * instrument mapping is verified
  * data is fresh
  * exchange/segment matches
  * quote fields are complete
  * fallback_used = true
  * source = "indstocks"
  * warning is shown in API and UI
* If Kite and INDstocks both return data but price mismatch exceeds tolerance, flag DATA_CONFLICT.
* In DATA_CONFLICT, do not calculate signals from that symbol unless fallback policy explicitly allows it.
* If no trusted provider returns data, return missing symbol with reason. Do not fabricate.

3. Provider mismatch guard

Add strict comparison:

For each symbol where both Kite and INDstocks data are available, compare:

* last_price
* prev_close
