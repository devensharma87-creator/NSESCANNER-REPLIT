B. TOKEN-REBIND P0 CORRECTION

The current report states that after a token rebind:

- the old provider token remains subscribed
- it stays in subscribedTokens
- incoming ticks are dropped because identity resolution was removed

This is not acceptable for the future 7,890-token universe because orphan subscriptions consume the 9,000-token entitlement and can exhaust the 1,110-token headroom.

Implement one safe contract:

Preferred:
- Atomically unregister the old token from identity resolution
- Unsubscribe the old token from the correct Kite ticker/shard
- Remove it from subscribedTokens only after unsubscribe handling
- Register and subscribe the new token
- Preserve one-token-to-one-identity and one-identity-to-one-active-token invariants

If the current single-ticker API cannot safely perform this atomically:
- Reject live token rebind
- Return an explicit TOKEN_REBIND_REQUIRES_SUBSCRIPTION_RECONCILIATION result
- Queue/record the identity for a future controlled resubscription cycle
- Keep the existing valid token active
- Do not silently install the new mapping
- Do not leave an orphan subscription

Do not create the three-shard architecture in this task.

Required tests:

1. Successful rebind leaves no old token in subscribedTokens.
2. Old token is unsubscribed exactly once.
3. Old-token ticks cannot update the new identity.
4. New token resolves to the existing canonical identity.
5. Failed unsubscribe does not create two active tokens.
6. Repeated rebind is idempotent.
7. Duplicate provider token remains rejected.
8. Subscription count does not grow after rebind.
9. Rebind cannot consume entitlement through orphan tokens.
10. No change to freshness thresholds or safety locks.
