CODER PROMPT — MASTER FIX: UNIFIED MARKET DATA BACKBONE, DATA PULLING, FRESHNESS, AND RECOVERY ACROSS ENTIRE WEBSITE

We are repeatedly facing data pulling issues across different tabs.

Examples already seen in production:

1. Topbar says KITE LIVE, but another module says data unavailable.
2. Kite page shows session active/feed connected, but F&O says:
    * daily bars unavailable
    * no live intraday
    * all indices suppressed
    * no signals
3. Scanner was Yahoo/info-only until source-honesty and Kite quote overlay were added.
4. Home needed separate source-honesty work.
5. Pre/Post reports are honest but many sections are still unavailable.
6. F&O alerts are firing because Kite session is active but F&O daily/intraday bars are not fetched.
7. We cannot keep fixing data issue tab by tab.

This is not acceptable for a professional Indian market analysis platform.

We need a unified market data backbone.

This task is not a UI beautification task.

This task is not a strategy tuning task.

This task is not one-tab repair.

This task is a full data backbone audit and repair plan, with implementation of the central missing pieces required to stop data-path fragmentation.

====================================================
OWNER REQUIREMENT

Data must not be compromised for any tab.

Every tab must use one reliable, source-honest, freshness-aware data backbone.

The system must never silently show stale, fake, unavailable, or mixed data as live/trade-grade.

But the system also must not become useless by showing everything as unavailable when Kite is active and data can be fetched or recovered.

We need professional-level behavior:

* fetch what can be fetched
* retry what can be retried
* isolate unsupported symbols/indices
* do not let one failed index block everything
* do not use Yahoo for trade-grade paths
* show exact reason if data is unavailable
* provide recovery action
* ensure every page consumes the same backbone

====================================================
DO NOT DO

Do not add unrelated features.

Do not change F&O strategy logic.

Do not change swing strategy logic.

Do not change scanner scoring formulas.

Do not change thresholds.

Do not enable broker execution.

Do not place real orders.

Do not mutate trading state except safe data cache/diagnostic/backbone metadata if required.

Do not hide warnings.

Do not fake missing data.

Do not use Yahoo fallback for trade-grade signals.

Do not mark data trade-grade unless it is Kite/trusted/local-Kite-derived and fresh.

Do not trim or rewrite replit.md.

Do not fix only one tab and call the problem solved.
