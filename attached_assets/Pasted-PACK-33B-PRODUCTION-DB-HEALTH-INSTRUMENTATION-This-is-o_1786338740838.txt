OBJECTIVE

Instrument the existing production DB health check so the current single `SELECT 1` measurement separates:

* pool connection acquisition time;
* SQL execution time;
* total time;
* pool state;
* connection reuse.

This must replace the current measurement—not add another periodic query.

IMPLEMENTATION

Modify the existing `measureDbLatencyMs()` path to use the same application pool:

1. Record pool counters before acquisition:

   * totalCount;
   * idleCount;
   * waitingCount.

2. Call `pool.connect()` and measure:

   * `acquireMs`.

3. On the acquired client, run one query only:

   SELECT 1 AS ok, pg_backend_pid() AS backend_pid

4. Measure:

   * `queryMs`;
   * `totalMs = acquireMs + queryMs`.

5. Record pool counters after the query.

6. Always release the acquired client exactly once in `finally`.

7. Preserve the existing timeout and failure handling.

8. Continue using `totalMs` for the existing system-mode threshold during this evidence phase. Do not weaken or change the threshold.

9. Store these fields in the existing system-mode health snapshot:

   * checkedAt;
   * dbTotalMs;
   * dbAcquireMs;
   * dbQueryMs;
   * poolTotalCountBefore;
   * poolIdleCountBefore;
   * poolWaitingCountBefore;
   * poolTotalCountAfter;
   * poolIdleCountAfter;
   * poolWaitingCountAfter;
   * backendPidChanged;
   * dbMeasurementStatus.

10. Do not expose raw PostgreSQL host, port, username, password, connection string or DATABASE_URL.

11. Add a one-way database-instance fingerprint:

SHA-256(normalized host + port + database name)

Return only the first 16 hexadecimal characters. Never return the source values.

12. Expose these diagnostics only through the existing authenticated system-mode diagnostic response. Do not create a public route.

13. Confirm the existing route’s exact authentication middleware. If it is not owner-protected, STOP and report:

BLOCKED_DIAGNOSTIC_ROUTE_NOT_OWNER_PROTECTED

Do not expose pool or database diagnostics to anonymous/subscriber sessions.

* acquisition failure;
* query failure;

* client released exactly once after query failure;

* existing system-mode thresholds remain unchanged;
* existing safety behaviour remains fail-closed.

Do not use source-regex tests as the primary proof. Invoke the production measurement function with controlled pool/client mocks.
