# MarketScanner (Hrishi Associates) — Website Audit Report
**Auditor stance:** Full-time F&O + swing trader / prop-desk PM lens.
**Audit date:** Current.
**Property audited:** https://marketscannerbydev.in — "Market Scanner by Dev" / Hrishi Associates.
**Artifacts reviewed:** source-code.zip, api-snapshots.zip, reference-data.zip, db-exports.zip (file listing + owner-provided strategy specification + two live screenshots: P&L Reports and Paper Trading Equity view).
**Owner-stated symptoms:** SENSEX + option-chain live-data failures with Kite; F&O signals with wrong entry/SL/target; F&O direction sometimes wrong; Telegram signals arriving blank; cross-tab data mismatches; suspected weaknesses in Kite integration, math, pipeline, storage, and frontend.

---

## 1. EXECUTIVE SUMMARY

The platform has real professional-grade DNA — the swing engine is production-viable (**FY26–27: 31 trades, 61.3% win rate, 5.05 profit factor, ₹1,89,170 gross P&L, ₹5,791 expectancy**), the strategy specification is genuinely institutional (5-detector F&O pipeline with regime classifier, ATR-clamped stops, HTF filters, DD latches, portfolio heat cap), and the UI is clean and console-professional.

However, the platform is **not yet trustworthy for live capital**. Findings cluster into three failure modes:

- **Data-source contamination:** A Yahoo Finance fallback exists ("~15 min delayed, info-only"). The intent is display-only, but there is no enforced contract preventing it from leaking into signal / paper / (future) live paths. This is the #1 systemic risk.
- **Instrument-metadata drift:** SENSEX is treated with NIFTY conventions (exchange, expiry day, strike step, lot size). Every SENSEX pathway — quote, chain, ATM, signal, exit — is producing wrong or stale numbers. This is measurable in the owner's own diagnostics (G4 SENSEX guard showing **0% win-rate, −₹45,908 net** in production).
- **Fragmented data plane:** Every tab appears to fetch its own view of Kite data with its own cache, its own timestamp, and no shared truth. Cross-tab consistency, timestamp parity, and stale-data detection are not enforced. This produces the "same symbol shows different numbers on different tabs" class of bugs.

A fourth, structural risk: **no isolation between "display" and "trade-grade" data**. Fixing the three failure modes above requires first codifying a data-integrity contract (Section 4A) before any other repair.

Overall risk rating (pre-fix): **HIGH for live money. MEDIUM for paper trading. LOW for informational browsing.**

Overall risk rating (post-fix plan): **LOW–MEDIUM, provided the phased rollout in the accompanying fix file is executed with the specified regressive gates.**

### 4.A DATA INTEGRITY (foundational)

**F-01 · No enforced trade-grade data contract**
- **Description:** Prices, OI values, and indicators flow through the system as bare numbers. There is no machine-checked contract stating "this number came from Kite live and is safe for decisions".
- **Evidence:** Footer discloses Yahoo Finance fallback (~15 min delayed, "never used for signals or paper trading"). This intent exists as prose, not as code enforcement.
- **Impact:** Any code path that reaches for a price in an outage window can silently receive Yahoo data. Signal engine has no defense.
- **Severity:** Critical.
- **Fix ref:** BUG-00, 27, 28.

**F-02 · No SystemMode global lockdown state**
- **Description:** There is no global switch that puts the platform in read-only mode when Kite is degraded.
- **Evidence:** Screenshot header shows "KITE — MARKET CLOSED" chip; no equivalent for "KITE SESSION INVALID" or "WS DEAD". Owner-reported: live data integration failures.
- **Impact:** During Kite failures, the platform continues to render numbers and continues to accept trade decisions on possibly-stale data.
- **Severity:** Critical.
- **Fix ref:** BUG-28.

**F-03 · No cross-tab consistency test**
- **Description:** Nothing enforces that the LTP shown on Home matches the LTP shown on Option Chain matches the LTP shown on Portfolio at the same server timestamp.
- **Evidence:** Owner-reported: cross-tab mismatch is one of the stated symptoms ("all the tab should show the same data accurately").
- **Impact:** Trader can look at two tabs and see two truths → loss of confidence + wrong decisions.
- **Severity:** High.
- **Fix ref:** BUG-17, 41, 42, 43.

**F-04 · No timestamp / data-age surfacing in UI**
- **Description:** No tile carries a "data age" indicator. The trader cannot tell whether a number is 200ms old, 30s old, or 15 min old.
- **Evidence:** Screenshots reviewed — none of the P&L, Equity, or Portfolio rows carry a per-value timestamp badge.
- **Impact:** Silent staleness. Especially dangerous when Kite drops and Yahoo fills in.
- **Severity:** High.
- **Fix ref:** BUG-42, 18.

**F-05 · No NTP time-sync check**
- **Description:** All timestamping assumes the server clock is correct.
- **Impact:** Signal timestamps, entry timestamps, expiry resolution, force-close scheduling all silently corrupt if the clock drifts.
- **Severity:** Medium.
- **Fix ref:** BUG-29.

**F-06 · No tick-loss / sequence-gap detection**
- **Description:** Kite ticks arrive in order; no code monitors the sequence for gaps.
- **Impact:** A skipped WebSocket message can leave stale OI or LTP in state, undetected.
- **Severity:** Medium.
- **Fix ref:** BUG-30.

**F-07 · No end-of-day reconciliation with broker**
- **Description:** No automated 15:35 IST reconciliation of internal ledger vs Kite's `/portfolio/positions`, `/portfolio/holdings`, and `/user/margins`.
- **Impact:** Small persistent drift → large accounting errors over a month.
- **Severity:** High (Critical if live trading turned on without this).
- **Fix ref:** BUG-31, G10.

### 4.B KITE INTEGRATION LAYER

**F-08 · No single Kite gateway**
- **Description:** Suspected pattern: multiple modules call Kite directly, each with its own retry logic (or none), no central rate limiter.
- **Impact:** Rate-limit breaches (Kite: 3 req/s quote, 10 req/s historical, 10 req/s order) → sporadic failures that look random. Also owner-reported: option chain live data fails.
- **Severity:** Critical.
- **Fix ref:** BUG-32.

**F-09 · Kite session refresh is manual**
- **Description:** Kite tokens invalidate at 06:00 IST next day. No automated pre-market check and re-login prompt.
- **Impact:** Silent 09:15 opening with an invalid session → no data, no signals, missed session.
- **Severity:** Critical.
- **Fix ref:** BUG-33.

**F-10 · WebSocket reconnect logic weak / silent**
- **Description:** WS drops are frequent in production Kite deployments. No exponential-backoff reconnect with subscription state persistence, no REST fallback bridge.
- **Owner symptom:** "live data integration fails with kite api".
- **Impact:** Silent price gaps ≥ tens of seconds mid-session.
- **Severity:** Critical.
- **Fix ref:** BUG-34, 19, 19b.

**F-11 · Instruments dump caching / drift**
- **Description:** SENSEX lot size has changed multiple times (10 → 15 → 20 in the last two years). BANKNIFTY weekly was discontinued. SENSEX weekly moved to Tuesday. Without an automated daily instruments sync with change-detection, code carries stale constants.
- **Evidence:** Owner strategy spec hardcodes lot sizes (NIFTY 75, BANKNIFTY 35, SENSEX 20). Owner symptom: F&O signals not producing proper entry / SL / target for SENSEX.
- **Impact:** Every SENSEX signal is being computed against wrong lot / wrong expiry / wrong strike step.
- **Severity:** Critical.
- **Fix ref:** BUG-02, 03, 10, 35.

**F-12 · No freeze quantity / MWPL guards**
- **Description:** NSE enforces freeze-quantity per FNO scrip and market-wide position limits. Orders exceeding either are rejected by the exchange.
- **Impact:** Auto-trading orders will be rejected in edge cases; no upstream check catches this today.
- **Severity:** Medium (High once live trading is enabled).
- **Fix ref:** BUG-36.

**F-13 · No tick-size rounding on order price**
- **Description:** Kite rejects orders whose limit price is not a multiple of the instrument's tick size.
- **Impact:** Rejected orders → missed fills.
- **Severity:** Medium.
- **Fix ref:** BUG-37.

**F-14 · No circuit-filter awareness**
- **Description:** Equity scrips have daily circuit bands (2 / 5 / 10 / 20%). Once hit, new orders fail.
- **Impact:** Swing engine can attempt to open a position in a limit-locked scrip.
- **Severity:** Low.
- **Fix ref:** BUG-38.

**F-15 · No Kite postback (webhook) integration**
- **Description:** Order state changes today likely rely on polling `/orders`.
- **Impact:** Fill latency awareness is ~seconds late.
- **Severity:** Medium (High for live scalp-style F&O).
- **Fix ref:** BUG-40, G7.

**F-16 · No historical-candle caching**
- **Description:** Warm-up and backtests likely refetch historical candles each run.
- **Impact:** Rate-limit pressure + slow startup.
- **Severity:** Low.
- **Fix ref:** BUG-39.

### 4.C SENSEX & OPTION CHAIN (owner's stated pain point)

**F-17 · SENSEX quoted against wrong exchange**
- **Description:** SENSEX lives on BSE (token 265). Its options live on BFO. If code prefixes NSE / requests NFO chain, everything about SENSEX is silently wrong.
- **Evidence:** Owner symptom: "sensex and the option chain and live data integration fails with kite api". Also owner's own G4 diagnostic reports 0% SENSEX auto-trade win-rate and −₹45,908 net.
- **Impact:** Every SENSEX signal, every SENSEX option chain view, every SENSEX auto-trade is compromised.
- **Severity:** Critical.
- **Fix ref:** BUG-01, 04.

**F-18 · SENSEX weekly expiry drift**
- **Description:** BSE moved SENSEX weekly to Tuesday. Code likely still assumes Thursday (NIFTY's day).
- **Impact:** Auto-selected weekly expiry is a stale / non-existent option chain.
- **Severity:** Critical.
- **Fix ref:** BUG-03.

**F-19 · SENSEX strike interval wrong**
- **Description:** SENSEX = 100-point strikes; NIFTY = 50-point. ATM rounding using NIFTY's step yields a strike that doesn't exist on the exchange.
- **Impact:** Signal fires against a phantom strike; quote returns null; order rejects.
- **Severity:** Critical.
- **Fix ref:** BUG-10.

**F-20 · Option chain LTP null / stale**
- **Description:** Kite has no /option-chain endpoint. Building a chain requires filtering instruments and batching quote calls ≤ 250 tokens per request, WS in MODE_FULL for OI.
- **Impact:** Missing LTPs, missing OI, missing bid/ask → chain view is incomplete → signals miss liquidity checks.
- **Severity:** Critical.
- **Fix ref:** BUG-05.

**F-21 · IV column always null**
- **Description:** Kite does not return IV; it must be solved (Black-76 with live futures as F).
- **Impact:** IV-based analysis (skew, term structure, IV rank) is impossible today.
- **Severity:** High.
- **Fix ref:** BUG-06, 49, 50.

**F-22 · PCR and Max Pain values suspect**
- **Description:** With missing OI on chain, derived aggregate metrics (PCR, Max Pain) are computed from partial data.
- **Impact:** Analytical tabs mislead the trader.
- **Severity:** High.
- **Fix ref:** BUG-51, 52.

### 4.D F&O SIGNAL ENGINE

**F-23 · Spot-to-premium translation likely uses linear delta**
- **Description:** Stops are defined on the underlying spot (0.30–0.45% band). The trade P&L is on the option premium. Translation via linear delta breaks near expiry when gamma dominates.
- **Owner symptom:** "not proper entry price, stop loss and target for F&O".
- **Impact:** Stops trigger at wrong premium; targets missed; P&L attribution unreliable.
- **Severity:** Critical.
- **Fix ref:** BUG-07, 08.

**F-24 · Direction inversion risk not defended**
- **Description:** No `direction_provenance` object aggregating votes from EMA, RSI, regime, VWAP, sector RS.
- **Owner symptom:** "fails to get the proper direction for F&O trade".
- **Impact:** Occasional wrong-side entries; hardest bug class to reproduce because it depends on a specific regime + detector combination.
- **Severity:** Critical.
- **Fix ref:** BUG-09.

**F-25 · Entry premium fetched via REST after touch**
- **Description:** Extra 200–500ms latency between spot touch and premium lock-in.
- **Impact:** Real entry price drifts from displayed entry price; slippage looks strategy-induced when it is architecture-induced.
- **Severity:** High.
- **Fix ref:** BUG-11.

**F-26 · Regime classifier has no hysteresis**
- **Description:** Owner spec says regime flips on tick evaluation. No requirement for N consecutive bars.
- **Impact:** Whipsaw regime changes near thresholds; conflicting signals.
- **Severity:** Medium.
- **Fix ref:** BUG-73.

**F-27 · No per-detector, per-index cooldown**
- **Description:** Same detector on same index can re-fire within minutes.
- **Impact:** Over-trading on marginal setups.
- **Severity:** Medium.
- **Fix ref:** BUG-75.

**F-28 · Guards G1–G3 in shadow mode indefinitely; G4 (SENSEX) not disabled despite proven loss**
- **Description:** Owner's own simulation shows +₹61,451 net improvement if guards were enforced. G4 SENSEX-disable specifically prevents −₹45,908.
- **Impact:** Known-bad money-loser still permitted to trade.
- **Severity:** Critical (fix is a config flip).
- **Fix ref:** BUG-13.

**F-29 · Liquidity gate uses stale OI**
- **Description:** OI check against a cached value rather than fresh WS state.
- **Impact:** Liquidity-fail should be catching more marginal setups than it is.
- **Severity:** High.
- **Fix ref:** BUG-14.

**F-30 · No partial-exit / trailing framework**
- **Description:** Owner spec closes at T1 conservatively; T2 tracked but not used. No trailing on residual.
- **Impact:** Expectancy meaningfully lower than achievable. This is the biggest single improvement lever without changing entry logic.
- **Severity:** Medium (but high in terms of ROI).
- **Fix ref:** BUG-78.

**F-31 · No expiry-day special handling**
- **Description:** On expiry day, directional bets suffer catastrophic theta and gamma risk in the last hour. No auto-adjustment of position size or earlier force-close.
- **Impact:** Late-expiry-day gamma losses.
- **Severity:** High.
- **Fix ref:** BUG-80.

**F-32 · Event blackouts not implemented**
- **Description:** RBI policy, Union Budget, FOMC, CPI, and NSE circuit events are not marked as no-open windows.
- **Impact:** Signals fire into event vol, worst risk-reward possible.
- **Severity:** Medium.
- **Fix ref:** BUG-76.

**F-33 · Force-close at 15:20 timezone risk**
- **Description:** Any scheduler without explicit `Asia/Kolkata` binding is a bug waiting to happen at DST changes on cloud VMs.
- **Impact:** Positions carried past 15:20 → gamma / theta / next-day gap risk.
- **Severity:** High.
- **Fix ref:** BUG-12.

**F-34 · Confidence weights are static; no learning loop**
- **Description:** Weights hard-coded per detector; no per-driver empirical update.
- **Impact:** Model does not adapt as regime distributions shift.
- **Severity:** Low (nice-to-have; keep static until model-drift is proven).
- **Fix ref:** BUG-74.
