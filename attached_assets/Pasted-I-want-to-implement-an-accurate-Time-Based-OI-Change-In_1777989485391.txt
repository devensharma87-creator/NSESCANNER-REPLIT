I want to implement an accurate Time-Based OI Change / Intraday OI Delta feature for my options open interest dashboard.

Context:
My website already shows option-chain OI data for NIFTY/BANKNIFTY-style instruments. I want a feature similar to the screenshots I provided, where users can select a time window such as Last 3 min, Last 5 min, Last 10 min, Last 15 min, Last 30 min, Last 1 hr, Last 2 hr, Last 3 hr, or All / Full Day. The chart and summary must show how Call OI and Put OI changed during that selected time window.

Feature name:
Time-Based OI Change / Intraday OI Delta.

Core principle:
Do not rely on the exchange/vendor `changeinOpenInterest` field for this feature. That value usually represents change from previous day close or a vendor-defined baseline, not the selected intraday time window.

The correct calculation must always be:

OI Change = OI at selected end snapshot - OI at selected start snapshot

For each strike:

Call OI Change = Call OI(end) - Call OI(start)
Put OI Change  = Put OI(end) - Put OI(start)

For totals:

Total Call OI Change = Sum of Call OI Change across selected strikes
Total Put OI Change  = Sum of Put OI Change across selected strikes

This feature must compare two stored timestamped OI snapshots.

Important:
My current implementation is not giving an accurate result and does not show the real picture of OI changes in a time-based scenario. Please inspect the existing codebase, find how OI data is currently fetched, stored, calculated, and displayed, then correct the implementation end-to-end.

Do not remove existing dashboard features. Extend the current system.

4. API LOGIC
==================================================

Step 1:
Find the end snapshot.

For live mode:
- End snapshot = latest complete valid snapshot for selected symbol and expiry.
- It must be within market hours.
- It must not be stale.

For historical/slider mode if end_time is provided:
- End snapshot = latest complete snapshot at or before requested end_time.
- Do not use future snapshots after requested end_time unless explicitly required and clearly exposed.

Step 2:
Find the start time.

For fixed window:
requestedStartTime = endSnapshotTime - selected window duration

Examples:
Last 3 min  = endSnapshotTime - 3 minutes
Last 30 min = endSnapshotTime - 30 minutes
Last 2 hr   = endSnapshotTime - 120 minutes

For All / Full Day:
requestedStartTime = first valid market snapshot at or after 09:15 IST for the same trading day.

Step 3:
Find the start snapshot.

Use this selection rule:
- Prefer the latest complete snapshot at or before requestedStartTime.
- If no previous snapshot exists, use the nearest snapshot after requestedStartTime only if it is within +60 seconds.
- If no suitable snapshot exists, return a clear no-data response.

Do not silently use a wrong snapshot.

Step 4:
Start and end snapshots must be complete enough to compare:
- same symbol
- same expiry
- same strike
- same option_type
- same snapshot_batch_id group for each selected snapshot

Step 5:
Match strikes that exist in both start and end snapshots.

If a strike exists only in one snapshot:
- exclude it from delta calculation
- include it in debug logs as skipped/missing

Step 6:
Calculate strike-level deltas:

callOiChange = callOiEnd - callOiStart
putOiChange  = putOiEnd - putOiStart

Also calculate Cr values:

callOiChangeCr = callOiChange / 10000000
putOiChangeCr  = putOiChange / 10000000

Step 7:
Calculate totals:

totalCallOiChange = sum(callOiChange)
totalPutOiChange  = sum(putOiChange)

Step 8:
Calculate current total OI at end snapshot:

totalCallOiEnd = sum(callOiEnd)
totalPutOiEnd  = sum(putOiEnd)

Step 9:
Calculate PCR values correctly.

Total PCR at end time:

pcr = totalPutOiEnd / totalCallOiEnd

PCR change over selected window:

pcrChange = pcrEnd - pcrStart

Where:
pcrStart = totalPutOiStart / totalCallOiStart
pcrEnd   = totalPutOiEnd / totalCallOiEnd

PCR OI Change ratio:

pcrOiChange = totalPutOiChange / totalCallOiChange

Important correction:
PCR OI Change must be Put OI Change divided by Call OI Change, not Call divided by Put.

Examples:
If Call OI Change = +3.28 Cr and Put OI Change = +6.57 Cr:
pcrOiChange = 6.57 / 3.28 = 2.00 approximately.

If Call OI Change = -11.42 Cr and Put OI Change = -9.20 Cr:
pcrOiChange = -9.20 / -11.42 = 0.81 approximately.

Handle division by zero safely:
- If totalCallOiChange is zero, return null for pcrOiChange.
- Do not show Infinity or NaN on frontend.

Also include an absolute version if useful:

pcrOiChangeAbs = abs(totalPutOiChange) / abs(totalCallOiChange)

But the main dashboard value should match the existing screenshot behavior.
