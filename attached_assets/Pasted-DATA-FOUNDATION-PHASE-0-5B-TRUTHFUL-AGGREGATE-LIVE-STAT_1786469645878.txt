BACKGROUND

The current defect is:

deriveQuoteStatus() returns LIVE_TICKS when quoteCount > 0.

That proves only that at least one quote exists. It does not prove:

- Required-universe coverage
- Subscription coverage
- Tick coverage
- Per-instrument freshness
- Missing instruments
- Pending token reconciliation
- Provider conflict
- Market-open/market-closed correctness
- Complete NSE/BSE/index coverage

Today the feed subscribes to only approximately 50 equities and 8 distinct index tokens. The approved future target is approximately 7,890 mapped NSE/BSE/index tokens, but the authoritative runtime universe manifest is not implemented yet.

The website must not describe partial legacy coverage as complete live-market coverage.

OBJECTIVE

Replace count-based aggregate LIVE status with one centralized, fail-closed, freshness-aware and coverage-aware health contract.

Do not hardcode 7,890 as a permanent universe count. Listing counts change. Coverage must ultimately derive from a versioned, authoritative, reconciled subscription manifest.

Rules:

LIVE_COMPLETE is allowed only when all conditions hold:

1. Market is open.
2. coverageAuthority = AUTHORITATIVE_RECONCILED_UNIVERSE.
3. universeReconciliationValid = true.
4. requiredInstrumentCount > 0.
5. registeredInstrumentCount = requiredInstrumentCount.
6. subscribedInstrumentCount = requiredInstrumentCount.
7. freshInstrumentCount = requiredInstrumentCount.
8. staleInstrumentCount = 0.
9. unavailableInstrumentCount = 0.
10. conflictedInstrumentCount = 0.
11. pendingReconciliationCount = 0.
12. Every required identity has exact exchange-qualified identity.
13. No shard/provider health blocker exists.

A non-zero quote count must never be sufficient for LIVE_COMPLETE.

LIVE_PARTIAL means some authorized instruments have fresh ticks but complete authoritative coverage is not proven.

RECONCILIATION_PENDING must be surfaced whenever pending token reconciliation exists. Do not hide it behind a generic LIVE label.

CONFLICTED must fail closed for affected instruments and must be represented in aggregate blockers.

STALE means data exists but no longer meets the existing approved freshness policy.

UNAVAILABLE means no trustworthy current value is available.

D. MARKET-CLOSED SEMANTICS

Do not label a valid official closing value stale merely because the market is closed.

Distinguish:

- Market open + fresh tick
- Market open + stale/missing tick
- Market closed + verified current-session close
- Market closed + previous-session/old data
- Holiday/weekend with latest verified close
- Unknown or stale market calendar

MARKET_CLOSED_CURRENT requires:

- A valid canonical closing value
- Correct trading date/session
- Valid timestamp
- Exact identity
- No unresolved conflict
- Honest source/provenance

If only part of the required universe has a verified closing value, use MARKET_CLOSED_PARTIAL.

Do not change market-calendar rules or freshness thresholds in this task. Reuse the existing approved policies. If they cannot support the required distinction, stop and report the exact policy blocker.
